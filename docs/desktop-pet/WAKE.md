# 桌面宠物 · 系统睡眠 / 唤醒与渲染看门狗

## 1. 现象（2026-11-07）

电脑从 11-06 23:29 合盖，一直睡到 11-07 22:08，将近 23 小时。中间系统每十几分钟会在黑屏状态下后台醒来一下（DarkWake）。

开盖后宠物出了问题：
- 宠物窗照常移动，但骨骼不动。走路时像在"飘"，站着没有任何动作。
- 几分钟后自己恢复了。

## 2. 排查结论

- **状态机没问题。** 醒来后"起身 → 待机 → 走路"这几种切换，每一条都会重新放片段、解除暂停。
- **清醒时复现不了。** 用探针测过：同一套 `GLTFLoader` / VRM 片段、同一个模型，按 App 的 stop / play / 暂停顺序走一遍。
  - `scene.isPaused` 暂停 45 秒再恢复，动作立刻正常。
  - `isPlaying` 关了再开，动作也立刻正常。
  - 所以问题出在真正的系统睡眠里：渲染循环或动画时钟没跟上。具体是哪一个，事后分不出来。
- **原来查不了。** 宠物模块对睡眠 / 唤醒没有任何处理，也不写日志，事后看不到当时的状态。
- **顺带发现：** `scene.isPaused` 只停动画、不停渲染。宠物睡着时仍以约 20 fps 画同一个姿势，白白耗电。设计 §7.2 想省的电其实没省下来。

## 3. 做法

既然分不出是哪一种，睡前把渲染和动画都停干净，醒来从头重建一遍，再由看门狗兜底并写日志。

**睡前**

- 触发：`willSleep`、`screensDidSleep`、`sessionDidResignActive`（切走用户）。
- `PetEngine.suspend()` 停掉每帧定时器。DarkWake 时进程也会被唤起跑一会儿，不再对着黑屏换动作、攒一堆没渲染出来的片段切换。
- `PetModelView.suspended = true` 停渲染循环（`isPlaying`）和动画时钟（`scene.isPaused`）。

**醒来**

- 触发：`didWake`、`screensDidWake`、`sessionDidBecomeActive`、`com.apple.screenIsUnlocked`（解锁）。
- 等 1 秒，让屏幕起来。
- `engine.resume()`：勿扰 / 空闲马上重新判断（宠物关着的话引擎不跑，见下）。
- `restartAnimations`：**只在真的歇过（睡前那三种通知来过）时**当成刚换上这个形象一样重来。
  单纯锁屏又解锁（屏没熄）不重建：重建会把蹲着的人从 T 字淡回去再重新坐一遍、把睡着的人重播一遍、把正在做的动作硬切掉（2026-11-08 代码审查）。卡住的情况看门狗照样兜底。
  - 清掉骨骼和表情上的所有动画（助推器的火焰闪烁也在里面，清完装回去）；
  - 重置片段状态，重新眨眼；
  - 渲染循环关了再开；
  - 按当前姿态重新放片段：直接切过去、不从绑定姿势淡入；正在歇脚就接着原来那种坐着的循环。
- 宠物所在的屏还在不在（合盖接上 / 拔掉外接屏）：不在任何屏上就放到最近那块屏的可见区里（`rescueIfOffscreen`；接上 / 拔掉显示器、改分辨率时也查）。
- 2 秒后看一眼有没有挡住正在用的窗口（屏幕和窗口可能都变了），见 SETTLE.md §4。

**从打盹醒来**（你回到电脑前）

- 引擎这一拍只把 sleep 改成 idle，不往下排别的；`wakeDuration`（按形象的「起身 + 伸懒腰 / 打哈欠 / 招手」最长那串）之内不溜达、不歇脚、不跳，
  睡着期间到点的这些计时器都往后推 —— 不然醒来那一拍就直接坐下或走掉，起身动作播不出来。

**宠物关掉**

- 退场播完后引擎停转（`PetEngine.setHidden`，和系统睡眠的 suspend 分开记，系统醒来不会把关掉的宠物跑起来），点击穿透计时器、窗口观察器也停；打开时先恢复再出场。

**睡着（打盹片段播完）**

- `isPlaying` 也一起关，真正停止渲染。
- 来提醒、醒来、做互动时再打开。

## 4. 看门狗（`PetModelView.checkHealth`）

每秒检查一次。只在该动的时候检查：宠物开着、没睡、系统没睡、窗口看得见。

| 发现 | 处理 |
|---|---|
| 连续 2 秒没出帧（`SCNSceneRendererDelegate` 计数，`PetRenderHeartbeat`） | 渲染循环关了再开 |
| 5 秒后仍然没有帧 | 整个重建（`restartAnimations`），30 秒内最多一次 |
| 出帧了，但循环片段上 hips / spine / head / 上臂 / 大腿 2 秒纹丝不动 | 整个重建，20 秒内最多一次 |

"循环片段"指待机、走路、趴着、掉落、被拎着。只看这几种：打盹、跳起这类停在最后一帧的片段本来就不动，不算。

## 5. 日志

```bash
log show --last 1d --predicate 'subsystem == "com.baobox.app" AND category == "pet"'
```

会出现的几条：

| 日志 | 含义 |
|---|---|
| `system rest (…)` / `system wake (…)` | 睡了 / 醒了 |
| `restart animations: …` | 重建了，后面跟原因 |
| `watchdog: no frames …` | 不出帧 |
| `watchdog: … frozen on looping clip …` | 出帧但骨骼冻住 |
| `relocate (…)` | 挪窝，见 SETTLE.md |

下次再卡，看出现的是哪一条，就知道是不出帧还是骨骼冻住，也能看出重建有没有救回来。
