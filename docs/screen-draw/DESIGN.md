# 屏幕标注画笔

对应 issue：[#14 新功能：屏幕标注画笔](https://github.com/qiaob/baobox_mac/issues/14)

## 本质：换一块画布

讲解、演示、录屏时要「边说边画」，先截图再标注的节奏是断的。

截图模块的标注引擎（`AnnotationTool` / `AnnotationStyle` / `AnnotationOp` / `AnnotationRenderer`）
本来就是「在一个 bounds 坐标系里画一堆 op」，**画在冻结的选区图上还是画在一层透明浮层上，
对它没有区别**。所以这个功能不是新写一套绘制，而是给同一套引擎换一块画布。

嵌在截图模块内（同 OCR、长截屏），不新立 `ToolModule`。

## 文件

```
Sources/Modules/Screenshot/
├── ScreenDrawController.swift    # 单例：多屏画布 + 工具条 + 两种状态的生命周期
├── ScreenDrawOverlayWindow.swift # 每屏一扇透明画布窗
├── ScreenDrawView.swift          # 绘制交互（复用 AnnotationRenderer）
└── ScreenDrawToolbar.swift       # 自己的工具条
```

## 两个状态

| | 绘制态 | 穿透态 |
|---|---|---|
| 画布 | 吃掉全部鼠标事件 | `ignoresMouseEvents = true` |
| 本 App | 激活（`NSApp.activate`） | 不干预，焦点还给前台 App |
| 笔迹 | 可继续画 | 留在屏幕上，只是不能改 |
| 工具条 | 可点 | 可点（独立浮窗，不受画布影响） |

**失焦即自动转穿透**：⌘Tab 切走、点通知、切 Space 之后，画布还盖在最上层吃掉全部点击 ——
用户既点不到切过去的 App，也点不到菜单栏（画布在 `.screenSaver` 级，压着菜单栏和 Dock），
键盘也不再进画布（Esc / ⌘Z 全失灵），观感就是「卡死」。所以监听
`didResignActiveNotification`，一失焦就转穿透：笔迹留着、机器照常用，想继续画点工具条上
那个手的图标即可（它是画布的子窗口，任何时候都可点）。

**为什么绘制态要激活本 App**：Esc 退出、⌘Z 撤销、⌫ 清空都要走键盘，不激活就收不到键。
这与长截屏控制条「全程不抢焦点」的取舍相反，但那里用户要滚下面的页面，这里用户就是在跟画布交互。

穿透按钮的图标与配色会跟着切（`hand.raised` ↔ `hand.raised.slash` + accent 染色）——
用户必须一眼看出现在点得动下面还是点不动。从穿透切回绘制时会重新抢一次键盘焦点，
否则 ⌘Z / Esc 会静默失灵。

## 工具条必须是画布的子窗口

工具条与画布**同级**（`.screenSaver`）并挂成画布的子窗口（`addChildWindow(_:ordered:.above)`）。

这不是风格问题：`.popUpMenu` 是 101、`.screenSaver` 是 1000，工具条只要比画布低，
就会被自己的画布整个盖住——看不见，点下去还会在画布上画出一笔，功能直接不可用。
同级 + 子窗口关系才能保证稳定压在画布之上（截图工具条同样的做法）。

对应地，退出时要**先摘子窗口再关画布**，顺序反了会留下孤儿子窗口。

## 为什么不复用 `AnnotationToolbar`

那条工具条的动作是「取消 / 贴图 / 保存 / 复制」（外加长截屏、取字），
屏幕标注要的是「清空 / 穿透 / 退出」——**两组动作没有交集**。
硬做成一个「可配置显示哪些按钮」的工具条会把两边都拖累，
还会让截图那条路径的改动天天波及屏幕标注。

真正值得共用的是绘制引擎，那部分已经 100% 共用了。工具条这点重复（图标按钮工厂 + 色板）
是可接受的代价。

## 不提供的两个工具

- **马赛克**：没有底图可打码，`AnnotationRenderer` 的马赛克分支依赖 `mosaicImage`，
  屏幕标注恒为 nil，工具条里直接不出这个按钮。
- **文字**：文字输入要求画布窗口成为 key 并持续持有键盘焦点，与「尽量少打扰前台 App」
  冲突最大（演示中激活输入框可能让 Keynote 退出演示态）。这次先不做，
  等穿透模式在真实演示场景里跑一段时间再决定要不要补。

## 多屏：范围可选，默认只铺当前屏

设置页「屏幕标注 → 画布范围」二选一（`screenshot.drawScreenScope`）：

| | 行为 |
|---|---|
| **仅当前屏幕**（默认） | 只在鼠标所在那块屏铺画布，**其余屏幕完全不受影响**，可以边画边在那边操作 |
| 所有屏幕 | 每屏一扇画布，走到哪块屏都能画 |

默认单屏是因为画布会吃掉整屏的鼠标事件，把所有屏一起盖住太霸道；双屏用户的常见场景
恰恰是「一块屏演示、另一块屏看讲稿/操作」。改动在下次开始标注时生效。

多屏模式下**笔迹各自独立**（与截图 overlay 一致）。撤销/重做只作用于
「最近一次落笔的那块画布」——多屏下"撤销全部屏幕"是反直觉的。

`NSScreen.screens` 为空时（所有显示器休眠、外接屏热插拔的瞬间）直接放弃启动：
没有画布就没有任何退出入口，`isRunning` 会永久卡在 true——这是截图 overlay 踩过的同一个坑。

## 入口

- 菜单：截图 → 「屏幕标注」/「结束屏幕标注」（标题随状态变）
- 快捷键：`screenshot.draw`，**出厂不绑定**（沿用易冲突组合的一贯做法）
- 键盘：Esc 退出并清笔迹、⌫ 只清笔迹、⌘Z / ⇧⌘Z 撤销重做

## 与录屏并存

录屏进行中唤起画笔，笔迹会被录进去——这正是主场景之一。
工具条本身也会进画面（`RecordingController` 只排除了自己的 HUD 与边框）；
真要把工具条排除掉，需要把它的 windowID 加进录制过滤，属于后续增量，本次不做。
