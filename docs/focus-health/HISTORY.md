# 专注历史（#104）

> 状态：已实现（2026-11-10）。和设计稿不一样的地方都标在 §5。

## 1. 要解决的问题

专注计时只存「现在这一轮」（`state.json`）和提醒定义（`items.json`），用了几周也看不到自己专注了多少。

## 2. 记什么

每结束一段就往 `~/Library/Application Support/Baobox/FocusHealth/history.jsonl` 追加一行（只追加、不改写，坏行跳过）：

| 字段 | 说明 |
|---|---|
| `kind` | `focus` / `shortBreak` / `longBreak` |
| `start` / `end` | 这一段的起止（专注从按下开始算，暂停的时间不算进 `seconds`）。ISO 8601、UTC、取整到秒 |
| `planned` | 计划秒数（整数） |
| `seconds` | 实际专注 / 休息的秒数（整数；专注 = 各段相加，去掉暂停） |
| `outcome` | `done`（到点）/ `doneEarly`（提前结束 · 算完成）/ `discarded`（提前结束 · 不算）/ `skipped`（休息被跳过） |

一行长这样：

```json
{"end":"2026-11-10T01:25:00Z","kind":"focus","outcome":"done","planned":1500,"seconds":1500,"start":"2026-11-10T01:00:00Z"}
```

- 写入点（都在改 `session` 之前记，记的是这一段的样子）：
  - 专注：`finishFocus`（到点 = `done`；用户点「提前结束 · 算完成」/ 暂停卡片的「结束这一轮」= `doneEarly`）、
    `endFocusEarly(countAsDone: false)`（`discarded`）。
  - 休息：`finishBreak`（到点 / 休息画面做完 = `done`，休息画面被跳过 = `skipped`），以及另外两个提前结束休息的地方
    —— `endCycle`（卡片「结束」、菜单「结束休息」）和休息中直接 `startFocus`（「再来一轮」），都记 `skipped`。
- `FocusSession` 加了 `roundStartedAt`：`start` 时记下，暂停 / 继续不变，`complete` / `discard` 清掉。
  旧版本的 `state.json` 没有这个键，解出来是 nil，这时开始时刻按「结束 − 秒数」算。
- 专注的结束时刻：到点的取**计划结束的时刻**（App 关着期间过了点，关着的那段不算进去，`seconds` 封顶为计划时长）；
  暂停中结束的就是现在。休息的开始 = 计划结束 − 休息时长，结束 = 现在（不晚于计划结束）。
- 只留最近 400 天（按本地日期，结束时刻早于「今天 0 点往前 400 天」的去掉）：启动时后台读，有去掉的行（含崩在半截、
  没有换行的最后一行）就整份重写一次；干净的文件不重写。
- 看不懂的行（坏行，或以后更新版本写的新种类 / 新结果）读的时候跳过，但**文件里原样留着**（重写时接在后面）：
  装回旧版本的构建（别的分支装的包会盖掉 /Applications 里的），启动时不会把新版本记下的东西删掉。
- 追加前看一眼文件最后一个字节：不是换行（上次崩在半截）就先补一个换行，新的一行不会粘在坏行后面一起丢掉。
- 写失败按 #101 的做法报（`StorageWriteFailure`，数据名「专注记录」）。读、追加、重写和 `state.json` 用同一个串行队列，
  先后不乱；退出时同步写 `state.json` 也就顺带等这些写完。

## 3. 怎么看

- **设置 → 专注与健康** 最上面一行：「今天 75 分钟 · 本周 6.5 小时 · 连续 4 天」。
  - 今天 / 本周 = 结果为 `done` / `doneEarly` 的专注秒数之和；一轮算在它**结束**的那天；周从系统设定的每周第一天算起
    （`Calendar.current` 的 `firstWeekday`）。
  - 连续天数 = 到今天（今天还没有就到昨天）为止，每天至少一轮算完成的专注。
  - 时长两小时以内写分钟（「75 分钟」），再长写小时、最多一位小数（「6.5 小时」）。
  - 还没完成过一轮专注时，这一行是一句引导：「还没有专注记录。完成一轮专注后，这里显示今天、本周和连续天数。」
- **菜单栏 → 专注与健康** 二级菜单顶部、状态那行下面一行（置灰）：「今天专注 75 分钟」。菜单栏倒计时项的菜单是同一份。
- 统计读内存：控制器启动时后台读进历史，算好 `historySummary`（`@Published`），记一轮完成的专注、导入、翻日时重算；
  菜单构建只读它，不碰磁盘。
- 不做图表（不用 Swift Charts，项目约定）。以后要看更细，可以用数据导出（`docs/data-export/DESIGN.md`）拿到原始记录。

## 5. 和设计稿不一样的地方

- **休息的写入点多了两个**：设计稿只列了 `finishBreak`，但休息还会经 `endCycle` 和「休息中直接开始下一轮」结束。
  不记的话这两种休息在历史里凭空消失，所以也记成 `skipped`（§2）。
- **App 重启时丢掉的长休息不记**：休息画面随进程没了，启动时直接结束那段长休息（原有行为），这一段不进历史。
- **坏行跳过但不删**：设计稿只说「坏行跳过」；整份重写（裁剪、导入）时如果把看不懂的行一起扔掉，装回旧版本就会删掉
  新版本的记录，所以它们原样留在文件里，只有崩在半截的最后一行会去掉（§2）。
- **菜单那一行放在状态行下面**：设计稿写「二级菜单顶部一行」。状态行（「专注中 · 剩 12:34」）是现在在发生的事，
  仍放第一行；「今天专注 N 分钟」紧跟其后，两行都在第一条分隔线上面。今天还是 0 分钟时也显示（「今天专注 0 分钟」）。

## 6. 不做

- 不把健康提醒（喝水、站立、护眼）记进历史：它们是点一下就过去的提醒，记了也没人看。
- 不上传、不同步。
