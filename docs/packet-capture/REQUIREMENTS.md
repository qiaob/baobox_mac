# 网络抓包 — 需求文档

> 版本：v2.0（2026-11-20）。取代 v1.0（2026-07-23，自研内核）。
> 配套：同目录 `TECH_DESIGN.md`（技术方案）；旧方案留档在 `TECH_DESIGN_V1.md`。
> 定位：Baobox 的一个 `ToolModule`（`id: "netcapture"`，名称「网络抓包」，symbol `network`）。

## 1. 背景与这一版的变化

v1 用 Network.framework 自研了一个 HTTP(S) 中间人代理。它只认 HTTP/1.1，HTTP/2 和 WebSocket 透传看不到内容，TLS 那段没在真机验证过，模块自 #103 起暂缓、不编译。

v2 的两个决定（用户 2026-11-20 确认）：

1. **内核换成 mitmproxy**（MIT 协议），作为子进程运行。HTTP/2、HTTP/3、WebSocket、改写、重放都是现成的。
2. **mitmproxy 直接打进 App 包**，装好就能用，不做首次下载。

Baobox 自己做 mitmproxy 没有的部分：原生界面、一键配置、手机接入、和 AI 的结合。

用户的原始诉求不变：Mac 和手机都能抓 HTTPS；配代理、装证书要省事；有开关，不用时不占资源；能把抓到的包交给 AI。这一版加一条：**开箱即用** —— 不看文档，点一下就能抓到包。

## 2. 术语

- **引擎**：包内的 `mitmdump` 进程。开始抓包时启动，停止时退出。
- **Flow**：一次 HTTP 事务（请求 + 响应 + 元数据），或一条 WebSocket 连接。
- **CA**：引擎生成的本地根证书。设备安装并信任它之后，这台设备的 HTTPS 才能被解密。
- **未解密**：流量照常通过，但看不到内容（没装证书、证书固定、或用户选择不解密）。

## 3. 开箱即用：五个场景

窗口空着的时候问一句「你想抓什么」，下面五张卡片，每张一个按钮。点了之后该做的配置全部自动做，停止时全部还原。

| 场景 | 点一下做的事 | 需要用户做的 |
|---|---|---|
| 这台 Mac | 启动引擎；把系统代理指向它；CA 没装就装并信任 | 第一次在系统的验证框里验证一次（密码或 Touch ID） |
| 终端 / 脚本 | 启动引擎；在偏好终端里开一个已带好代理与证书环境变量的会话；另有「复制环境变量」 | 无 |
| iPhone / iPad | 启动引擎并允许局域网设备；显示一个二维码 | 扫码，在页面里点「装证书」「配代理」，到系统设置里开启信任 |
| Android | 启动引擎并允许局域网设备；检测到 adb 设备就一键设代理、推证书；没有就显示二维码 | USB 调试已开时：在手机上确认安装证书 |
| 模拟器 | iOS 模拟器：给已启动的模拟器装根证书（流量走 Mac 的系统代理）。Android 模拟器：经 adb 设代理、推证书 | 无 |

场景可以叠加（比如同时抓 Mac 和一台手机）。窗口顶部的「抓：…」下拉随时增减。

**必须据实告诉用户的限制**（写在对应卡片上，一行）：

- Android 7 起，App 默认不信任用户安装的证书。只有调试包（`network_security_config` 允许用户证书）的 HTTPS 能解密，其余显示「未解密」。
- 做了证书固定的 App 解不开，自动放行并标「未解密」，不影响它上网。
- 网页扫码无法给 Android 设代理（系统限制），只能 adb 或手动填。配置页把主机名和端口分开、各带一个复制按钮，并给一个直达 Wi-Fi 设置的按钮，把手填压到最少。
- iOS 装完证书后还要手动到「设置 → 通用 → 关于本机 → 证书信任设置」里打开开关。
- iPhone 的「一键配代理」要知道 Wi-Fi 名称，而新版 macOS 不让 App 读取它，所以要用户在手机面板里填一次；不填就在手机上手动填代理地址。

## 4. 功能清单

### 第一版（看）

| # | 功能 | 验收标准 |
|---|---|---|
| 1 | 开始 / 停止 | 开：引擎起来，1 秒左右可用。关：引擎退出、端口释放、系统代理还原。**关闭时没有任何后台进程** |
| 2 | 五个场景的一键配置 | 见 §3；每个场景点一下后，对应来源的请求出现在列表里 |
| 3 | 解密 HTTPS | 已信任 CA 的设备，HTTP/1.1 与 HTTP/2 的明文可见 |
| 4 | WebSocket | 握手作为一条 Flow；详情里有消息列表（方向、时间、文本或大小）。Android（Chrome）、Mac 上的 App、iOS 模拟器里的 Safari 都实测抓到。苹果的 WebSocket 只走 SOCKS 代理，所以「这台 Mac」会把系统的 SOCKS 代理也指过来。真机 iPhone 还不行（技术方案 §1） |
| 5 | 握手失败自动放行 | 某个域名的 TLS 握手被客户端拒绝后，这个域名在本次抓包里改为透传，列表里标「未解密」和原因 |
| 6 | 解密范围 | 全部 / 只解密这些域名 / 这些域名不解密；抓包中改动立即生效 |
| 7 | 列表与详情 | 请求一发出就进列表（进行中状态），响应到了补全。详情：概览 / 请求 / 响应 / 原始；JSON 美化、图片预览；gzip、deflate、brotli、zstd 自动解压，头里没声明但正文其实是 gzip / zlib / zstd 的也认出来解开 |
| 8 | 筛选 | 左栏按来源（本机、每台设备）和域名筛；顶部搜索 URL 与正文；方法、状态码过滤；清空 |
| 9 | 设备管理 | 新的局域网设备第一次连上，要在 Mac 上点「允许」才放行；设备可改名 |
| 10 | 证书 | 一键安装并信任、查看状态、一键移除；二维码配置页（装证书 / 配代理 / 关代理） |
| 11 | 带走 | 复制为 cURL、复制为 Markdown、导出 HAR |
| 12 | 交给 AI | 本地 MCP 开关（现有 9 个工具不变）、「发送到 Claude Code」 |

### 第二版（改）

改写规则（用本地文件替换响应、转发到另一台服务器、改请求头与正文）、断点、编辑后重发、屏蔽域名。mitmproxy 都有对应能力，这一版只做界面与规则管理。

### 以后再看

WireGuard 模式（手机装 WireGuard 扫码，不认代理的 App 也能抓）、只抓某一个 Mac App（依赖 mitmproxy 的系统扩展）、弱网模拟（mitmproxy 没有）、gRPC / protobuf 视图、会话存盘。

## 5. 界面

### 5.1 窗口（三栏，默认 1080×660）

```
┌──────────────────────────────────────────────────────────────────┐
│ ● 停止   抓：这台 Mac ▾   🔍 搜索 URL / 内容             证书 ✓  │
├───────────┬──────────────────────────────┬───────────────────────┤
│ 全部  128 │ GET  200 api.x.com /v1/user  │ 概览 请求 响应 原始   │
│ 本机   86 │ POST 401 api.x.com /v1/login │                       │
│ iPhone 42 │ WS   101 chat.x.com /socket  │ { "error": "expired", │
│ ───────── │ GET  ⋯   cdn.x.com  /a.png   │   "code": 401 }       │
│ 域名      │ …                            │                       │
│  api.x.com│                              │ [复制 cURL]           │
│  cdn.x.com│                              │ [发给 Claude Code]    │
└───────────┴──────────────────────────────┴───────────────────────┘
 抓包中 · 192.168.1.23:9090 · 2 台设备 · 128 条
```

- **顶部**：开始 / 停止；「抓：…」下拉（五个场景，可多选，每项右侧是它的状态）；搜索；证书状态；最右「⋯」（本地 MCP 开关、导出 HAR、设置）。
- **底部状态条**：运行状态、代理地址（点击复制）、设备数、条数。
- **关窗口不等于停止**：正在抓时关掉窗口，抓包继续，菜单栏里能看到状态并停止。
- **左栏**：来源（全部、本机、每台设备，带计数；右键改名、清空这台的包）和域名（按请求数排序）。取代 v1 的设备 Tab 条。
- **中栏**：方法、状态码、协议（h2 / ws 才标）、host、path、耗时、大小、时刻。进行中的请求状态码位置显示「⋯」。未解密的行用次要色。
- **右栏**：概览 / 请求 / 响应 / 原始；WebSocket 多一个「消息」。
- **空状态**：没在抓时，中栏和右栏换成 §3 的五张卡片。
- **待允许的设备**：窗口顶部一条提示「192.168.1.45 想通过这台 Mac 上网 · 允许 / 拒绝」，同时经 `NotifyCenter` 发一条通知。

### 5.2 菜单栏二级菜单

抓包的所有操作都在窗口里做，菜单只负责把窗口打开（用户 2026-11-21 定）。

```
没在抓：
打开抓包窗口…

正在抓：
[置灰] 抓包中 · 128 条
停止抓包
打开抓包窗口…
```

- 「停止抓包」只在正在抓时出现。窗口关掉后抓包还在继续（手机可能还连着，系统代理也还指着引擎），得有个地方能停。
- 代理地址、手机二维码、本地 MCP 开关都不放菜单：前两个在窗口里（底部状态条、手机场景的卡片），MCP 开关在窗口右上角的「⋯」和设置页。
- 快捷键只有一个「打开抓包窗口」，出厂不绑定。

### 5.3 设置页

一项一行：端口、列表上限、单条正文上限、停止时清空、解密范围、证书（状态 + 安装 / 移除；机器上还留着 v1 的旧证书时多一行「移除」）、本地 MCP（开关 + 注册到 Claude Code / Codex）。最上面一个「打开抓包窗口」。配色与方法、状态码的颜色沿用 v1（`docs/design/ui-design-v1.html` 的令牌）。

## 6. 非功能需求

- **资源**：关闭时零开销。开启时引擎常驻约 100 MB（实测 12.3.1 空载 101 MB）。列表上限默认 1000 条，单条正文上限默认 5 MB，超出的正文不捕获、标「已截断」。
- **包体**：App 增加约 88 MB（解开后），压缩包增加约 56 MB。只带 Apple 芯片版引擎；Intel Mac 上模块显示一行「需要 Apple 芯片」并置灰。
- **隐私**：抓到的内容只在内存里，清空或退出 Baobox 即丢（设置里可选「停止时清空」，默认关：停下来看刚抓到的东西是最常见的用法），只有用户主动导出才落盘。CA 私钥只在本机支持目录，权限 600。窗口首次打开时提示一次「仅用于调试自己的设备和应用」。
- **安全默认值**：没有手机场景时，引擎只监听 `127.0.0.1`。有手机场景时才监听局域网，且新设备要在 Mac 上允许。控制通道是引擎进程的标准输入输出，不开额外端口。
- **稳定**：引擎意外退出时状态变为失败并还原系统代理。Baobox 崩溃时引擎自行退出；下次启动发现系统代理还指着自己就还原。
- **降级**：包里没有引擎（开发构建没跑 `make vendor`）时，模块显示一行置灰引导，不报错。
- **本地化**：`netcapture.*`，en + zh-Hans。扫码配置页是给手机浏览器的网页，中英并排，不走 `L()`。

## 7. 明确不做（第一版）

改写、断点、重发（第二版）；绕过证书固定；HTTP/3 的界面区分（引擎支持，列表里按 HTTP 显示）；抓包内容同步或共享；Windows / Linux。
