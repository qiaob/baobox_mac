# WireGuard 多台设备：一台一张二维码，添加时起名（方案）

## 0. 用户要的是什么（原话，2026-11-22）

> 这里会显示设备，如果我连接多个设备会显示什么？感觉不好区分，能直接显示手机型号/名称 之类的吗

讨论后选了「方案 A」：每台设备一张自己的二维码，添加时就起好名字；不靠从请求里猜型号（方案 B，没选）。

看第 1 版示意图时用户问「二维码直接展示了，那么右上角的添加设备有什么用？」，接着提「点击添加设备后，再出二维码吗？」—— 第 2 版改成卡片上只列设备、二维码在添加流程里出现（§6），用户回「可以」。

## 1. 现在的问题

- 只有一份密钥（`<supportDir>/wireguard.json`）、一个 UDP 端口（51820）、一张二维码。隧道里客户端地址是引擎写死的 `10.0.0.1`。
- 两台手机扫同一张码 = 同一把钥匙：引擎认成同一个对端，回包只发给最近发过包的那台，两台都时断时续（按 WireGuard 的机制推的，没实测）。
- 设备栏只有一行「WireGuard 设备」；右键重命名按 `10.0.0.1` 存，改了等于所有隧道设备一起改。
- 型号 / 名称从流量里拿不到：设备名（「xx 的 iPhone」）不在任何请求里；型号只有部分 Android App 的 User-Agent 带型号代码，iPhone 只能看出系统版本。所以名字由用户在添加时给。

## 2. 做法

**一台设备 = 一份密钥 + 一个 UDP 端口 + 一张二维码 + 一个名字**。引擎同时开多个 WireGuard 监听（每台一个 `--mode wireguard:<密钥文件>@<端口>`），桥按「这条连接是从哪个监听进来的」认设备。

为什么不在一个端口上挂多个对端：引擎底层（`mitmproxy_rs.wireguard.start_wireguard_server(…, peer_public_keys: list[str], …)`）支持多个对端，但 mitmproxy 上层只传一个公钥，客户端地址也写死 `10.0.0.1`，改它就得改包里的引擎（包带原作者签名，不重签）。一台一个监听不用动引擎。

**已验证**（2026-11-22，包里的 mitmproxy 12.3.1）：

- `--mode regular@127.0.0.1:18080 --mode wireguard:wg1.json@52820 --mode wireguard:wg2.json@52821` 同时起来，`lsof` 看到两个 UDP 监听，两份配置各自打印、各用各的钥匙。
- 插件里 `ProxyMode.parse(spec)` 能拿到 `type_name == "wireguard"`、`data`（密钥文件路径）、`custom_listen_port`（端口）。连接上的 `client.proxy_mode` 是同一个类。

**没验证**：两台真设备同时连（实现后用模拟器 `baobox_capture_test` + 用户的 vivo 一起测）。

## 3. 数据

- 设备表 `<supportDir>/wireguard/devices.json`：`[{"id": "<uuid 小写>", "name": "vivo", "port": 51820}]`，数组顺序 = 列表顺序。
- 每台的密钥 `<supportDir>/wireguard/<id>.json`，格式不变（引擎认的 `{"server_key", "client_key"}`），权限 600，写法沿用 `WireGuardKeyFile`（临时文件 + 原子改名）。
- 端口：添加时分配，之后不变（二维码里写死了）。第一台用设置里的端口（默认 51820），之后取「已用的最大端口 + 1」，跳过代理 / SOCKS / MCP / 配置页正在用的端口。不提供单台改端口。
- **迁移**（首次启动新版本时，后台做）：已有 `wireguard.json` → 第一台设备，钥匙和端口都不变，**扫过旧码的手机照样能连**；名字取 `10.0.0.1` 的别名（用户改过的话），没有就叫「设备 1」；迁完删掉旧文件和 `10.0.0.1` 的别名。先写设备表、再搬密钥文件，中途失败下次重来不丢钥匙。
- 读写失败按约定报 `StorageWriteFailure`；设备表解析容错（坏的条目跳过、密钥文件缺了的条目不出二维码并提示「这台的钥匙丢了，删掉重新添加」）。
- 纯逻辑放 `Logic/WireGuardDevices.swift`（Foundation + CryptoKit，进 `BaoboxTests`）：设备表编解码、下一个端口、默认名、迁移步骤的判断。

## 4. 引擎与桥

- `EngineListeners.wireguardPort: UInt16?` 改成 `wireguard: [WireGuardListener]`（密钥文件路径 + 端口），每台一个 `--mode`。WireGuard 开关关着 = 空数组。
- 开关开着时添加 / 删除设备 → 监听组合变了 → 重启引擎（现有规则：监听只能启动时定）。重启会断开别的设备手上的连接，WireGuard 客户端自己会重连；列表不受影响。改名不重启。
- 桥：新增 `wireguard_device(client)` = `client.proxy_mode.data` 的文件名去掉 `.json`（即设备 id）。`request`、`tls`、`tcp_open`、`device` 事件在 `client` 之外多带一个 `"wg": "<id>"`（非隧道连接不带）。放行规则不变（仍按 `proxy_mode` 是 `wireguard` 认）。

## 5. 设备怎么显示

- 设备键：带 `wg` 的事件是 `wg:<id>`，其余仍是来源 IP。`Flow.deviceKey`、`TCPConnection.deviceKey`、MCP 的 `device` 参数都用它。
- 显示名：`wg:<id>` → 设备表里的名字；设备已经删了但列表里还有它的包 → 「已删除的设备」。局域网设备照旧（别名 → IP）。
- 设备栏、TCP 页的设备筛选、TCP 详情的「设备」字段都显示这个名字。设备栏右键「重命名」一台隧道设备 = 改设备表里的名字（配置页同步变），不再写别名表。
- 隧道设备的右键菜单：「重命名…」「清空这台设备的包」、分隔线、「在配置页里管理…」（切到配置页、选中 WireGuard）。「屏蔽此设备」不出现（隧道设备不走「允许」）。
- 图标：隧道设备用 `lock.shield`（和配置页 WireGuard 那一行一样），本机 `laptopcomputer`，局域网设备 `network`。

## 6. 配置页 WireGuard 卡片

**界面以示意图为准**：`mockups/wireguard-devices-starttls.html`（2026-11-22 用户确认的第 2 版；图 1–3 是这一节，图 4 是 §5 的设备栏，图 7 是设置页）。

```
WireGuard                                                   [开关]
手机装 WireGuard App，扫码。手机的流量全部经过 Baobox，不用设代理。
───────────────────────────────────────────────────────────────
设备                                              [＋ 添加设备]
┌───────────────────────────────────────────────────────────┐
│ 🛡 vivo          51820   ● 刚刚        [二维码] [改名] [删除] │
│ 🛡 测试 iPhone   51821   ● 3 分钟前    [二维码] [改名] [删除] │
│ 🛡 Pixel 模拟器  51822   ● 还没连过    [二维码] [改名] [删除] │
└───────────────────────────────────────────────────────────┘
新手机点「添加设备」，起个名字后扫码。每台一张码，两台扫同一张会互相挤掉。
Mac 的 IP 变了要重新扫码（点那台的二维码图标），或在 WireGuard App 里改端点。……
```

- **卡片上不直接放二维码**，只列设备：名字、端口、最近活动、三个小按钮（二维码 / 改名 / 删除，右键菜单里也是这三项）。
- **最近活动** = 这台最后一个包的时间（HTTP 和 TCP 都算），没有就是「还没连过」；绿点 = 几分钟内有包。只在内存里，不落盘（重启后「还没连过」直到它再来包）。
- **添加设备是一个两步的小窗**：
  1. 起名：输入框先填好「设备 N」并全选；「取消」/「下一步」。
  2. 点「下一步」才建钥匙、分端口、写设备表（开关开着就重启引擎）；小窗换成二维码 + 端点 +「复制配置」+ 现有的三步说明；底下一行状态：转圈「等手机连上…（打开隧道后随便开个 App）」，收到这台的第一个包后变成绿色「已连上，刚刚收到「设备 N」的第一个包」；按钮「完成」。不等直接点「完成」也行。
- 已有设备点**二维码图标**：同一个小窗的第 2 步，标题「测试 iPhone 的二维码」，状态行照样按最近活动显示。
- **改名**：第 1 步的小窗，标题「重命名设备」，按钮「保存」。**删除**：确认框「删除「Pixel 模拟器」？扫过这张二维码的设备将连不上。已经抓到的包还在列表里。」
- 开关打开时一台都没有 → 直接弹出添加小窗，名字填好「设备 1」。
- 开关关着：列表照常显示、能改名删除；「添加设备」和二维码图标置灰，列表下一句「打开 WireGuard 后才能添加设备、看二维码」（关着时不显示任何密钥相关内容，沿用现在的规则）。
- 配置页左栏 WireGuard 那一行的副标题：开着时显示「N 台设备」，不再显示单个端点。
- 设置页：「WireGuard 端口」改叫「新设备起始端口」（小字：以后添加的设备从这个端口往后排；已经有的不变）；「重新生成 WireGuard 密钥」去掉（删掉再添加就是换钥匙）。

## 7. MCP

- `get_config`：`wireguard_endpoint` 换成 `wireguard_devices: [{id, name, port, endpoint}]`。
- `get_wireguard_config`：加可选参数 `device`（名字或 id），不给就是第一台。
- 新增 `add_wireguard_device(name)`（返回新设备和它的配置文本）、`remove_wireguard_device(device)`、`rename_wireguard_device(device, name)`。
- `list_devices`：隧道设备给 `wg:<id>` 和名字。

## 8. 这一次不做

- 从请求头猜型号（方案 B）。
- 单台改端口、端点用 `.local` 名字。
- 一个端口挂多个对端（要改包里的引擎）。

## 9. 做完的标准

1. 单元测试：设备表编解码与容错、下一个端口（跳过占用、紧贴上限）、迁移判断、`EngineListeners` 多个 WireGuard 的 `--mode` 参数。
2. 真引擎（端口用 196xx 一带，别碰 9090–9092 和 51820）：两个 WireGuard 监听 + 桥，模拟器连其中一个，事件里的 `wg` 是对的那台；添加 / 删除时引擎按预期重启。
3. 界面渲染探针：WireGuard 卡片 0 / 1 / 3 台、开 / 关、添加弹窗、删除确认；设备栏两台隧道设备 + 本机 + 一台局域网设备。中英文各一套。
4. xcstrings 校验、`make build`、测试全过；只做本地提交。
5. 要用户在真机上试的：vivo + 模拟器（或第二台手机）同时连、各自的包落在各自名下；旧二维码迁移后照样能连；iPhone。

## 10. 实现时和方案不一样的地方（2026-11-22）

用户看得见的行为都照上面做了；下面是方案没写到、或者写法和实际做法不一样的地方。

| # | 方案原写法 | 实际做法 | 为什么 |
|---|---|---|---|
| 1 | 没写 | 桥的「握手失败自动放行」表和「已经报过的没解密行」按**设备键**记（隧道设备 `wg:<id>`，其余是来源 IP），不再按 IP | 隧道里每台都是 `10.0.0.1`：一台手机不信任证书，不能让另一台也被放行 |
| 2 | 新设备端口 =「已用的最大端口 + 1」 | 取「起始端口」和「起始端口以上已用的最大端口 + 1」里大的那个，跳过代理 / 配置页 / SOCKS / MCP 的端口；排到 65535 还没有就从起始端口、再从 1024 起找空的 | 设置页写的是「以后添加的设备从这个端口往后排」：用户把起始端口改大了，新设备要从新端口开始；平常两种写法结果一样 |
| 3 | 默认名「设备 N」 | N = 已有台数 + 1，和已有的名字重了就往上加 | 删掉中间一台后不会出现两个同名 |
| 4 | 隧道设备右键「清空这台设备的包」 | 这一项对所有设备都改叫「清空这台设备的包」，HTTP 和 TCP 两页里这台的都清掉（原来是「清空这台设备的请求」，只清 HTTP） | 一个菜单里两种叫法容易糊涂；手机经隧道来的包多半在 TCP 页 |
| 5 | 「在配置页里管理…」= 切到配置页、选中 WireGuard | 另外把列表里这一台高亮（点别的行换高亮） | 示意图的说明是「跳到 WireGuard 并选中这台」 |
| 6 | 已有设备的二维码小窗「状态行照样按最近活动显示」 | 有包时是「已连上，最近一个包：3 分钟前」，没包时和添加时一样转圈等 | 「刚刚收到第一个包」只对刚加的设备成立 |
| 7 | 没写 | 一台都没有时列表里一行「还没有设备」；钥匙丢了的那台在名字下面一行橙色「这台的钥匙丢了，删掉重新添加」，二维码图标是灰的 | 方案只写了要提示，没写放哪 |
| 8 | 「最近活动」= 最后一个包的时间 | 算的是 Baobox 收到这台事件的时间：HTTP 请求 / 响应 / WebSocket 消息、没解密的 TLS 行、TCP 连接开始和每段数据 | 和事件里的时间戳差不到一秒，不受手机时钟影响 |
| 9 | `get_config` 的 `wireguard_devices: [{id, name, port, endpoint}]` | 每台另带 `key`（`wg:<id>`，给 `list_flows` 等的 `device` 参数用），钥匙丢了的多一个 `key_missing: true`；`add_wireguard_device` 的 `name` 可以不给（默认「Device N」）；一台都没有时 `get_wireguard_config` 返回错误、提示先 `add_wireguard_device`（原来会顺手建一份密钥） | 加设备是有后果的动作（WireGuard 开着时引擎要重启），不该被「看一下配置」顺带触发 |
| 10 | `list_devices`：隧道设备给 `wg:<id>` 和名字 | 名字写成 `WireGuard: vivo`，删了的写 `(deleted WireGuard device)` | 让 AI 一眼分清隧道设备 |
| 11 | 没写 | 不再把 `10.0.0.1` 叫「WireGuard 设备」：隧道设备一律按 `wg:<id>` 认，`10.0.0.1` 就是普通 IP | 家里的 Wi-Fi 也可能有 `10.0.0.1` 这台局域网设备，原来会被叫错 |
| 12 | 没写 | 两台删掉的设备还各有包时，设备栏里是两行「已删除的设备」（各自的设备键不同，不合并） | 合起来就分不清哪些包是哪台的了；这种情况少见 |
| 13 | 设置页小字只改「新设备起始端口」那一行 | 设置页底下那句「端口、WireGuard 端口和正文上限在引擎下次启动时生效」里去掉「WireGuard 端口」 | 起始端口只影响以后添加的设备，不用重启 |
| 14 | 迁完删掉旧文件和 `10.0.0.1` 的别名 | 别名不删，只拿来给迁出来的那台取名（独立审查 #9） | 家里的网段可能真有一台 `10.0.0.1` 的局域网设备，那个名字是给它起的 |
| 15 | 迁移「中途失败下次重来不丢钥匙」 | 写设备表失败时设备表保持「没读完」：配置页「添加设备」是灰的、MCP 加设备报错，下次打开 WireGuard 或加设备时再读一次；另外旧的 `wireguard.json` 还在时，分配端口把旧端口当作占用（审查 #3） | 原来读失败也算读完了，接着「添加设备」会占掉旧二维码的端口，迁移再成功时旧钥匙就作废了 |
| 16 | 没写 | 读设备表时，目录里有一把表里没有的 `<uuid>.json`、又恰好只有一台缺钥匙：把这把钥匙还给它（审查 #4）。多于一把或多于一台缺钥匙就不动 | 用户常同时开着 worktree 构建和 /Applications 里那份，共用支持目录；两个同时迁移时钥匙会落在表里没有的 id 下。回收还能修好已经发生的情况，比加文件锁好 |
| 17 | 「设备表解析容错（坏的条目跳过）」 | 有条目被丢或整个文件读不出来时，先把原文件复制成 `devices.broken-<时间>.json`（同 Mock 规则），再继续（审查 #6） | 不然下一次写盘就把坏条目永久丢了 |
| 18 | 没写 | 搬旧钥匙、删钥匙失败都报「存储写入失败」（不再 `try?` 吞掉）；搬不成的那次直接用旧文件给这台出码、开监听，不提示「钥匙丢了」，下次启动再搬（审查 #7）。这种情况下这次运行里这台的包按 `10.0.0.1` 记（桥从密钥文件名认设备，旧文件名不是设备 id） | 钥匙一样，扫过旧码的手机照样能连；写盘问题让用户知道 |
| 19 | 没写 | 设备名：换行、制表等控制字符换成空格，截到 64 个字符（界面输入、MCP、读设备表都一样，审查 #10） | MCP 传进来的名字不过滤会把列表撑成几行 |
| 20 | 没写 | 设备表还在读时先开后关 WireGuard：读完的回调照最后一次的意图来，不再把它打开（审查 #12） | 原来读完会把用户已经关掉的开关又打开 |

## 11. 验证记录（2026-11-22）

全程没有改系统代理（系统代理控制器是只记录调用的桩）、没碰钥匙串、没用用户的支持目录，端口都在 196xx。

**单元测试**（`WireGuardDevicesTests` 17 个 + `EngineLaunchTests`、`CaptureEventTests` 里新加的）：设备表编解码与容错（坏 id、大写 id、空名字、缺端口、端口是字符串 / 布尔 / 越界 / 0、重复 id、重复端口、整个文件坏了）、下一个端口（第一台用起始端口、最大 + 1、跳过保留端口、起始端口改大 / 改小、紧贴 65535、低于 1024 按 1024）、默认名、迁移判断（6 种情况）与迁移执行（临时目录：钥匙和端口不变、权限 600、旧文件搬走、再启动不重迁、写了设备表没搬文件的半截状态接着搬、新装什么都不写、钥匙丢了的设备照样在表里）、多个 WireGuard 的 `--mode` 参数与监听组合相等性、事件里的 `wg`（带、不带、不像设备 id 的当没有）。

**真引擎**（真实的 `NetCaptureSession` / `NetCaptureEngine` / `WireGuardDeviceStore` / `FlowStore` / `TCPStore` / `CaptureMCPServer` 编进一个宿主程序，包里的 mitmproxy 12.3.1 + 真桥脚本，代理 19640、WireGuard 从 19643 起），39 项全过：

| 做了什么 | 结果 |
|---|---|
| 支持目录里只放一份旧的 `wireguard.json`（Android 模拟器 `baobox_capture_test` 里的隧道「baobox」就是 11-21 用它的二维码配的，端点 `192.168.0.9:19643`），给 `10.0.0.1` 起过别名「旧手机」 | 迁成第一台：名字「旧手机」、端口 19643、密钥逐字节相同、权限 600；旧文件没了，别名删了 |
