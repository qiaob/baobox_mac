# 抓包的设置都放进「配置」页（方案）

## 0. 用户要的是什么（原话，2026-11-22）

> mcp开关不应该放在http抓包页面
>
> 还有一个问题，现在 现在配置页有一些配置，设置页也有一些配置，菜单栏还有一些快捷操作，我觉得这里需要重新思考一下，一个配置到底应该放在哪里？哪些配置需要快捷操作

讨论后定了下面的规则和挪法，看过示意图 `mockups/config-layout.html`（图 1–7）后回「可以开始做吧」。**界面以示意图为准。**

## 1. 规则（有自己窗口的工具）

1. 一个设置只放一个地方。
2. 抓包窗口的「配置」页 = 这个工具的全部设置。常用的在上面（来源、证书、解密、设备接入、MCP），不常改的数值放最下面一组「高级」。
3. 设置窗口里「网络抓包」那一页只留一句话 +「打开抓包配置」按钮。
4. 菜单栏只放窗口关着也必须能做的事：看状态、停止（抓包开着时系统代理指着 Baobox，关窗口不会停）、打开窗口。其余操作都要看结果，留在窗口里。
5. 快捷键只有「打开抓包窗口」，出厂不绑，不加别的。

这次只改网络抓包。要不要把规则写进仓库根 `CLAUDE.md`、推广到别的有窗口的工具，等用户看过效果再定。

## 2. 挪法

| 设置 | 现在 | 以后 |
|---|---|---|
| 本机 / 手动代理 / WireGuard / 给其他设备装证书 | 配置页 | 不变 |
| 这台 Mac 信任证书、移除信任、证书名称、重新生成证书、清理旧证书 | 配置页（只能装）+ 设置页 | 配置页「证书 → 这台 Mac」：这一行能点开，右边全在（图 2） |
| 解密 HTTPS 开关 + 解密范围（全部 / 只解密名单 + 两份名单） | 配置页 + 设置页（「范围…」跳出窗口） | 配置页：点「解密 HTTPS」那一行，右边是开关、范围、名单（图 1）；「范围…」链接去掉 |
| WireGuard 起始端口 | 设置页 | 配置页 WireGuard 详情底部（图 5） |
| 本地 MCP（开关、端口、注册进 Claude / Codex、脱敏） | 设置页 + HTTP 页「…」菜单 | 配置页「工具」组最后一行「本地 MCP」（图 3） |
| 代理端口、列表最多保留条数、单条正文上限、停止时清空 | 设置页「通用」 | 配置页最下面「高级 → 端口与上限」（图 4） |
| 导出 .har、Mock、过滤 | HTTP 页工具条 | 不变（对列表的操作，不是设置） |

## 3. 各块细节

- **左栏**：「证书」组的「这台 Mac」行加 chevron、可选中；「解密 HTTPS」行的小字说当前范围（「全部域名」「不解密 N 个域名」「只解密 N 个域名」）；「工具」组最后加「本地 MCP」（图标用一个「AI」意味的符号，开着时小字是 `127.0.0.1:<端口>`，行尾是总开关）；最下面新组「高级」一行「端口与上限」（小字「代理 9090 · 最多 1000 条 · 正文 5 MB」）；隐私说明仍在最底下。
- **解密 HTTPS**（图 1）：标题行带开关；一句说明；「范围」分段控件（「全部域名，除了下面这些」/「只解密下面这些」）；对应名单的文本框（每行一个）；说明里加一句「手机不信任证书的域名会自动放行，不用填进来。改了立即生效」。两份名单各自保留（和现在一样），改了立即发给引擎（现有的 `applyScopeFromSettings`）。
- **这台 Mac**（图 2）：设置页 `NetCaptureCertSection` 的全部内容和行为搬过来，确认框文案不变；旧版证书那一行只在钥匙串里还有旧证书时出现。
- **本地 MCP**（图 3）：标题行带开关；地址 + 复制；Claude Code / Codex 的注册状态与注册 / 移除；「给 AI 的请求头里隐藏鉴权信息」开关（小字说清楚：Authorization、Cookie、Set-Cookie 的值换成 `<redacted>`）；端口（小字：改了要关掉再打开；已注册的要重新注册）。
  **开关记住状态**：新键 `netcapture.mcpEnabled`（默认 false）；用户拨开关时写；`activate()` 时为 true 就启动服务。启动失败（端口被占）开关回到关，不改存的值以外的东西。
- **端口与上限**（图 4）：代理端口、列表最多保留（Stepper 200–5000 步长 100）、单条正文上限（1 / 5 / 20 MB）、停止时清空。说明：端口在下次开始抓包时生效（四个总开关全关再打开）。
- **WireGuard**（图 5）：详情最底下一行「新设备起始端口（UDP）」，键还是 `netcapture.wireguardPort`。
- **设置窗口**（图 6）：`settingsTab()` 只剩标题、一句话、「打开抓包配置」按钮（打开抓包窗口并切到「配置」页）。
- **菜单**（图 7）：
  - 菜单栏子菜单最后那项「网络抓包设置…」改成打开抓包窗口并切到「配置」页。框架要加一个可选项，让模块自己决定「设置」在哪打开（例如 `ToolModule` 加一个默认实现为 nil 的设置动作，`StatusItemController` 有就用它，没有就照旧开设置窗口）。其他模块不受影响。
  - HTTP 页「…」菜单：去掉「本地 MCP」开关；「设置…」改叫「抓包设置…」，切到「配置」页。
  - HTTP 页底部状态条的「MCP 运行中」留着。
- **MCP 的 `get_config` / `set_config`**：键不变；MCP 端口、脱敏仍然只读（AI 不能关掉脱敏，也不能改自己的端口）。

## 4. 这一次不做

- 别的模块（Claude Code / Codex 中心窗口、会议、手机互传）照这个规则调整。
- 改任何设置的键名或默认值（除了新增 `netcapture.mcpEnabled`）。

## 5. 做完的标准

1. 设置页原有的每一项都能在配置页找到、行为不变（逐项对照 `NetCaptureSettingsView` 原代码）；没有一项同时出现在两处。
2. 菜单栏「网络抓包设置…」打开的是抓包窗口的配置页；其他模块的「设置…」照旧。
3. MCP 开关：打开 → 重启 App（用探针或单元测试模拟 `activate()`）→ 服务起来；关掉 → 重启后不起。
4. 界面渲染探针：图 1–6 对应的状态各一张（中英文），900 宽下左栏不挤、右边不截断。
5. 测试、`make build`、xcstrings 校验全过；只做本地提交。

## 6. 实现时和方案不一样的地方（2026-11-22）

用户看得见的行为照上面做了；下面是方案没写到、或者写法和实际做法不一样的地方。

| # | 方案原写法 | 实际做法 | 为什么 |
|---|---|---|---|
| 1 | 证书名称「Baobox Capture CA · 2026-11-21」（示意图） | 只有名字 | 证书模块（`CaptureCA`）现在不读证书的生成日期；要加日期得解析证书，这次没做 |
| 2 | MCP「启动失败（端口被占）开关回到关，不改存的值以外的东西」 | 开关回到关，记住的值也改成关（下次启动不再自动开） | 按「只动存的值」理解：界面和记住的状态一致，不会出现「开关是关的、重启后却自己开了」 |
| 3 | 框架「加一个默认实现为 nil 的设置动作」 | `ToolModule.settingsAction: (@MainActor () -> Void)?`，默认 nil；`StatusItemController` 有就调它，没有照旧开设置窗口那一页 | 同方案，记一下名字 |
| 4 | 「解密 HTTPS」那一行的小字说当前范围 | 开关开着才显示（和别的行「开着才有小字」一致）；范围和名单在开关关着时照样能改 | 关着时写「不解密 3 个域名」容易让人以为还在解密 |
| 5 | 没写 | 打开左栏「本地 MCP」的开关时顺便选中这一行（右边是它的详情），和三个抓包来源的总开关一样 | 打开以后下一步通常是注册进 Claude Code / Codex |
| 6 | 没写 | 「最多 1000 条」「列表最多保留 1000 条」不加千分位 | 示意图如此；端口号也不加 |
| 7 | 设置窗口那页「只剩标题、一句话、按钮」 | 引擎用不了（Intel / 包里没有引擎）时那一页照旧只显示原因 | 那种情况下打开抓包窗口也只是同一句原因 |
| 8 | 没写 | 设置页原来那行「打开抓包窗口…」+「抓什么、怎么接其他设备都在抓包窗口里操作」去掉，换成方案里的一句话 + 「打开抓包配置」 | 一个入口就够 |

## 7. 验证记录（2026-11-22）

- **逐项对照原来的 `NetCaptureSettingsView`**：通用（端口、条数、正文上限、停止时清空）→「高级 → 端口与上限」；WireGuard 端口 → WireGuard 详情底部「新设备起始端口（UDP）」；解密范围（模式 + 两份名单 + 改了立即发给引擎）→「解密 HTTPS」详情；证书（信任状态、安装 / 移除信任、证书名称、重新生成 + 原来的确认框、旧版证书清理）→「这台 Mac」详情；MCP（开关、端口、注册进 Claude Code / Codex、脱敏开关、地址）→「本地 MCP」详情。设置页现在只剩标题、一句话、「打开抓包配置」；HTTP 页「…」只剩「导出 .har…」「抓包设置…」。每一项只在一个地方。
- **MCP 开关记住**（真实的 `CaptureMCPServer` 编进宿主程序，每一步是一次单独的进程运行，等于重启 App；`activate()` 里调的就是 `startIfEnabled()`）：从没开过 → 启动后不起；打开 → 在跑、记住了；下一次启动 → 自己起来、`capture_status` 有应答；关掉 → 停、记住了关；再下一次启动 → 不起；端口被另一个程序占着时打开 → 开关回到关、记住的也是关。7 项全过。
- **界面**（渲染探针，中英文各 13 张）：图 1 解密 HTTPS（全部域名除了… / 只解密…，1180 和 900 宽）、图 2 这台 Mac（已信任 + 旧版证书那一行、900 宽、未信任）、图 3 本地 MCP（开着、900 宽、关着时左栏没有地址）、图 4 端口与上限（1180、900）、图 5 WireGuard 详情底部的起始端口、图 6 设置窗口那一页。900 宽下左栏不挤、右边不截断。看图改掉的：条数带了千分位（「1,000」）。
- **没验证的**：菜单栏「网络抓包设置…」和 HTTP 页「抓包设置…」没真点过（没有界面自动化权限），编译过，走的是和设置窗口按钮同一个 `showConfig()`；其他模块的「设置…」没有声明 `settingsAction`，走原来的分支。
