# 抓包窗口重做：配置 / HTTP 包 / TCP 包（方案）

> 2026-11-21 定稿，用户逐条确认过。实现者先读 `TECH_DESIGN.md` §1（验证记录，尤其 §1.w–§1.z）和 `TOOLS.md` §9（做完的标准与坑）。
> **照文档实现**；实现中发现走不通的地方，就地改文档并在汇报里写明原因。

## 0. 用户要的是什么（原话）

- 「直接在首页放几个功能，不需要考虑现在的什么模拟器什么的」：1 配置本机，有三个开关 http / websocket / tcp；2 固定 IP 然后展示出来，用于其他设备手动配置；3 WireGuard App，直接展示一个二维码；4 配置证书，有个开关，启动后展示二维码和内网地址。
- 「上方不需要区分什么我的设备 / 其他设备了」；每张卡片「最上方有一个开关，然后下边有不同的开关」。
- 「最上方这里有三个 tab，一个配置，一个 http 包，一个 tcp 包，支持同时抓取」。WebSocket 不拆成单独的 tab（留在 HTTP 包里，加一个筛选）。
- 「模拟器、终端、Android USB 这几个排在后边吧」。
- 「mcp 需要支持配置 + 查看包，支持所有的配置」。
- 之前定的也都还算数：要有暂停；WireGuard 是手机的默认接法，端点用 IP；本机的 TCP 只抓得到走系统 SOCKS 的程序（用户已接受，开关旁边写明）。

## 1. 窗口结构

```
[ 配置 ] [ HTTP 包 128 ] [ TCP 包 5 ]                    ● 运行中 192.168.0.9:9090   [⏸ 暂停] [停止全部]
───────────────────────────────────────────────────────────────────────────────────────────────
（当前标签页的内容）
```

- 三个标签页在窗口内容区最上面一行（一条自己的标签条，不改系统标题栏）。标签上带数量。
- 右边是全局状态和两个全局按钮：
  - **暂停 / 继续**：对 HTTP 和 TCP 同时生效；只在引擎运行时可用；不记住，引擎每次启动都从「记录中」开始。
  - **停止全部**：把四张卡片的总开关全部关掉（引擎停、系统代理还原）。只在引擎运行时显示。
- 不再有「开始 / 停止」按钮、不再有「这台 Mac / 其他设备」两个开关、不再有「设备设置」面板 —— 都由「配置」页的卡片取代。
- 打开窗口时：引擎在跑就停在「HTTP 包」，否则停在「配置」。**打开卡片开关不自动切标签页**（用户在配置页上通常要连着开几个）。

## 2. 「配置」页

2×2 四张主卡片，下面一排三张小一号的次要卡片。每张主卡片右上角一个总开关。

```
┌ 本机 ─────────────────── [总开关] ┐  ┌ 手动代理 ──────────────── [总开关] ┐
│ 抓这台 Mac 上的流量                │  │ 其他设备在 Wi-Fi 的代理里手动填      │
│   HTTP / HTTPS          [开关]   │  │   主机 192.168.0.9  [复制]         │
│   WebSocket             [开关]   │  │   端口 9090         [复制]         │
│   TCP                   [开关]   │  │ （待放行的设备在这里：允许 / 拒绝）   │
└───────────────────────────────────┘  └───────────────────────────────────┘
┌ WireGuard ────────────── [总开关] ┐  ┌ 证书 ──────────────────────────────┐
│ 手机装 WireGuard App，扫码         │  │ 这台 Mac：已信任 / [安装并信任]      │
│  ┌──────┐ 端点 192.168.0.9:51820  │  │ 解密 HTTPS        [开关]  范围…    │
│  │二维码│ [复制配置]              │  │ 给其他设备装证书  [总开关]           │
│  └──────┘                         │  │  ┌──────┐ http://192.168.0.9:9091/ │
└───────────────────────────────────┘  └──┴──────┴─────────────────────────┘
┌ 模拟器 ─────────┐ ┌ 终端 / 脚本 ────┐ ┌ Android USB ────┐
```

### 2.1 引擎什么时候跑

- 四个总开关（本机、手动代理、WireGuard、给其他设备装证书）**任意一个开着，引擎就在跑；全关就停**。次要卡片里的操作（开终端、设模拟器）需要引擎时自己把它起起来（只起引擎，现有的 `ensureEngine`），之后由「停止全部」停。
- **总开关不跨启动保存**：App 启动时四个都是关的（Baobox 是开机自启的菜单栏 App，不能一启动就改系统代理、开监听）。子开关和各种取值保存。
- 引擎的监听组合由开关决定，变了就重启引擎一次（约 1 秒，列表不丢，和现在 `setLAN` 一样）：
  - HTTP 代理：`regular@<地址>:<端口>`，「手动代理」或「给其他设备装证书」开着时听 `0.0.0.0`，否则 `127.0.0.1`。
  - SOCKS：`socks5@127.0.0.1:<端口+2>`，照旧总开着、只听本机。
  - WireGuard：`wireguard:<supportDir>/wireguard.json@<WG 端口>`，「WireGuard」开着才加。
- 「给其他设备装证书」开着、「手动代理」关着时，引擎也听局域网（配置页的证书检测要连代理端口），但**局域网设备拿它当代理用要被拒**：桥加一个状态 `lan_proxy`（指令 `{"cmd":"lan_proxy","on":bool}`，启动时用选项给初值），为假时非回环、非隧道来源的普通请求一律 403（不发 `device` 事件，页面写「手动代理没有打开」）；发给引擎自己的、发给配置页的、证书检测、`check.baobox.invalid` 照常。

### 2.2 本机

总开关 = 现在的「抓这台 Mac」（走 `startMac` / `stopMac` 那套，证书没信任时照旧弹系统验证）。三个子开关（总开关关着时变灰但保留取值）：

| 子开关 | 键 | 默认 | 作用 |
|---|---|---|---|
| HTTP / HTTPS | `netcapture.mac.http` | 开 | 系统的 HTTP、HTTPS 代理指向引擎 |
| WebSocket | `netcapture.mac.websocket` | 开 | 记录 WebSocket 消息；需要系统 SOCKS 代理（苹果的网络库只让 WebSocket 走 SOCKS） |
| TCP | `netcapture.mac.tcp` | 关 | 经 SOCKS 进来的、不是 HTTP 的 TCP 连接记进「TCP 包」。旁边一行小字：只有走系统 SOCKS 代理的程序抓得到 |

- 系统 SOCKS 代理：**本机总开关开，且 WebSocket 或 TCP 任一开着**才设；否则不碰。`SystemProxyController.enable` 改成 HTTP、SOCKS 各自可选；抓包中任一开关变化就重新应用。注意 `restore()` 依赖「开启前的快照」，重新应用时不能把我们自己设的状态当成原状态存下来。
- 经 SOCKS、非 443 端口的 **TLS** 连接照旧原样放行、不记录（现有规则，不改：解开它们等于看邮件之类的私有协议）。

### 2.3 手动代理

- 总开关键 `netcapture.lan.proxy`（运行期状态，见 §2.1 不跨启动）。
- 显示主机和端口，各带一个复制按钮；一句话：Mac 的 IP 变了要重新填。
- 新设备第一次连上来仍要「允许」：待放行的设备列在这张卡片里（允许 / 拒绝），现在窗口顶上的提示条和通知也留着。
- iPhone 想用描述文件一键配手动代理，需要 Wi-Fi 名称：卡片里一个可选的输入框（现有的 `netcapture.wifiName`），旁边一行小字说明用途。

### 2.4 WireGuard

总开关开着时卡片上直接显示二维码；关着时显示占位（「打开后显示二维码」），不显示密钥相关的任何东西。

**已经在用户的 vivo 手机（Android）上验证过**（2026-11-21，临时引擎 `--mode wireguard:<密钥文件>@51820` + 桥 + 探针脚本，约 9 分钟）：920 条连接、631 次 DNS 查询进来，无报错；微信的 `mmtls` 请求、输入法的 WebSocket 握手、5 条原始 TCP 这些不认代理的流量都到了；HTTPS 大多没解密（手机没装当前证书 + App 不信任用户证书），握手失败后自动放行。隧道里客户端地址是 `10.0.0.1`，DNS 是 `10.0.0.53`。**iPhone 没试过。**

- 密钥文件 `<supportDir>/wireguard.json`，格式是引擎自己的：`{"server_key": <base64 32 字节>, "client_key": <base64 32 字节>}`（Curve25519 私钥）。没有就由 Baobox 生成（权限 600），这样没起过引擎也能出二维码；引擎读到已有的就用它（要实测它不会改写）。已验证：CryptoKit `Curve25519.KeyAgreement.PrivateKey(rawRepresentation:)` 从 `server_key` 算出的公钥与引擎打印的客户端配置一致。
- 客户端配置（二维码的内容，也是「复制配置」的内容）：

  ```
  [Interface]
  PrivateKey = <client_key>
  Address = 10.0.0.1/32
  DNS = 10.0.0.53

  [Peer]
  PublicKey = <server_key 的公钥>
  AllowedIPs = 0.0.0.0/0
  Endpoint = <Mac 的局域网 IP>:<端口>
  ```

- 端点用 IP（用户的决定）。卡片上一句话：Mac 的 IP 变了要重新扫码，或在 WireGuard App 里改端点；Baobox 没开着这个开关时隧道不通，手机会上不了网，记得在 App 里关隧道。
- 端口 `netcapture.wireguardPort`，默认 51820（UDP），设置页可改。设置页另有「重新生成 WireGuard 密钥」（确认框写明扫过的隧道会失效）。
- 隧道进来的设备（`10.0.0.x`）**不走「允许」**：有密钥才连得上。启动时放进 `baobox_allowed`。设备栏里默认叫「WireGuard 设备」。
- 一份配置 = 一个对端，同一时间一台设备。多设备不在这一版。
- 纯逻辑在 `Logic/WireGuardConfig.swift`（密钥文件读写与生成、公钥推导、配置文本），有单元测试（固定私钥对照已知公钥、文本逐行对照）。
- 桥：隧道里的 UDP、DNS 原样通过，不要拦；`is_this_machine` 在隧道模式下要实测 —— 手机经隧道访问 `http://<Mac 的 IP>:<配置页端口>/` 必须到得了配置页且不进列表（必要时加一个选项把 Mac 的 IP 传给桥）。

### 2.5 证书

三样东西：

1. **这台 Mac 的信任状态**：已信任 / 「安装并信任」按钮（现有的 `session.installCert()`）。
2. **解密 HTTPS** 开关（`netcapture.decryptHTTPS`，默认开）+「范围…」（跳到设置页的解密范围）。关 = 桥的解密范围用新的 `mode: "none"`：`tls_clienthello` 里一律 `ignore_connection`，`tls` 事件的 reason 用 `decrypt_off`，列表里这种行的说明和「握手失败」区分开。
3. **给其他设备装证书** 总开关：开 = 配置页服务（`ConfigPageServer`）开着，卡片上显示二维码和地址（带扫码即放行的口令，现有的 `landingPageURL`）；关 = 配置页服务关。

配置页（手机浏览器看到的）跟着变：请求是经隧道来的（来源 `10.0.0.x`，桥写在 `X-Baobox-Client` 里）时，不显示配代理 / 关代理，顶上写「已通过 WireGuard 连接」，只留装证书；「手动代理」没开时同样不显示配代理那几步。状态清单的文字要对两种接法都说得通。

### 2.6 次要卡片（排在后面）

三张小卡片，没有总开关，只有操作按钮，功能都是现成的：

- **模拟器**：给 iOS 模拟器装证书（说明里写「需要打开『本机』」，没开时点了提示一句，不替用户开）；设置 Android 模拟器（adb 设代理 + 推证书）。
- **终端 / 脚本**：打开抓包终端；复制环境变量。
- **Android USB**：列出 adb 设备，一键设代理 + 推证书、清代理（现有手机面板里 Android 那部分搬过来）。

现有的 `NetCapturePhoneSheet`、`NetCaptureDeviceSetup`、五张场景卡片、工具条上的两个来源开关都删掉，别留死代码和没人用的文案 key。

## 3. 「HTTP 包」页

就是现在的三栏界面，工具条去掉已经搬走的东西：

```
[🗑] [全文搜索…] GET POST PUT DELETE  2xx 3xx 4xx 5xx  [WS]                    [Mock] [⋯]
```

- 新增筛选按钮 **WS**：只看 WebSocket（`Flow.isWebSocket`）。
- 「⋯」里保留：MCP 开关、导出 HAR、设置。
- 没有任何请求时：引擎在跑显示「正在抓包，等待请求…」；没在跑显示一句「到『配置』里打开要抓的来源」和一个跳过去的按钮。
- WebSocket 消息的记录总开关：就是「本机」里的 WebSocket 开关吗？不是 —— 那个只管本机的 SOCKS。别的设备的 WebSocket 只要连接被解密就照常记录，不另设开关。

## 4. 「TCP 包」页

### 4.1 记什么

引擎当成原始 TCP 处理的连接（mitmproxy 的 tcp flow）：不是 HTTP、也不是能解成 HTTP 的 TLS。来源有两种：手机经 WireGuard 过来的；本机经 SOCKS 过来的（要开「本机 → TCP」）。**被放行的 TLS（握手失败、不在解密范围、关了解密）不在这里**，它们仍然是「HTTP 包」里的「TLS」行。UDP、DNS 不显示。

桥的新事件（钩子 `tcp_start` / `tcp_message` / `tcp_end` / `tcp_error`，探针脚本 `scratchpad/wgtrial/wgprobe.py` 可参考）：

```
{"event":"tcp_open","id","client","host","port","sni","ts"}
{"event":"tcp_data","id","from_client":bool,"size":N,"data":"<base64>","truncated":bool,"ts"}
{"event":"tcp_close","id","error":null|"…","ts"}
```

- 每条消息的 `data` 最多带 16 KB；每条连接累计超过正文上限（现有的 `baobox_body_cap`）后只报 `size`、不带 `data`。
- 暂停时不发（规则同 HTTP：`tcp_open` 没发过的连接，后面的 `tcp_data` / `tcp_close` 也不发）。
- 「本机 → TCP」关着时，来源是回环的 tcp 连接不发事件（指令 `{"cmd":"mac_tcp","on":bool}`，启动时给初值）。隧道来的总是发。

### 4.2 界面

两栏：左边连接列表，右边详情。

- 列表一行：开始时间、设备、目标（有 SNI 显示域名，否则 IP）`:端口`、状态（进行中 / 已关闭 / 出错）、时长、↑ 字节、↓ 字节。新的在上。
- 工具条：清空、搜索（目标地址 / 端口）、设备筛选。
- 详情：概览（目标、设备、起止时间、收发字节、消息数）+ 数据（按时间排的消息，每条标方向和大小，「十六进制 / 文本」切换，可复制；超过上限的只显示大小）。
- 数据模型放一个新的 `TCPStore`（上限条数和 `FlowStore` 用同一个设置），纯逻辑部分（十六进制排版、文本判定）进 `Logic/` 并有测试。

## 5. 暂停

桥指令 `{"cmd":"record","on":bool}`，每次引擎就绪都按当前状态发一遍；因为不记住，新启动时是 `on: true`，但开关引起的引擎重启要保持暂停状态。

- HTTP：`on` 为假时不发 `request`；发过的 flow 记 `flow.metadata["baobox_rec"] = True`，`response` / `error` / `ws` 只对带标记的发（暂停前发出的请求照常补全，暂停期间的不会恢复后冒出半条）。`tls` 行暂停时不发。
- TCP：同理，见 §4.1。
- `device`、`running`、`replay_failed` 照常；Mock、设备准入、重发不受影响（重发是用户主动点的，暂停时也照发照记）。

## 6. MCP：配置 + 看包，覆盖全部配置

现有工具保留（`list_flows`、`get_flow`、`search_flows`、`latest_flows`、`clear_flows`、`list_devices`、`capture_status`；`start_capture` = 打开本机（证书没信任时只起引擎，不弹验证，现有规则），`stop_capture` = 停止全部）。新增：

| 工具 | 作用 |
|---|---|
| `get_config` | 返回全部开关和取值：四张卡片的总开关与子开关、暂停、解密开关与范围、各端口、正文上限、条数上限、停止时是否清空、证书是否受信任、引擎状态，以及代理地址、WireGuard 端点、配置页地址 |
| `set_config` | 改上面任意几项（没给的不动），效果和在界面上拨一样。需要系统验证框的动作（信任证书）不做，返回里说明要用户在界面上点 |
| `get_wireguard_config` | 返回客户端配置文本（里面有隧道私钥；MCP 只听本机，说明里写清楚） |
| `list_tcp_connections` / `get_tcp_connection` / `clear_tcp` | TCP 包。`get_tcp_connection` 带 `limit`、`format`（hex / text） |
| `list_mock_rules` / `set_mock_rule` / `delete_mock_rule` | Mock 规则（新增、修改、启停、删除） |
| `replay_flow` | 重发一条（可带改动：方法、URL、请求头、正文） |
| `allow_device` / `deny_device` | 待放行设备 |

`set_config` 改到端口这类「下次启动才生效」的值时，返回里写明。脱敏开关（`mcpRedactAuth`）对新工具同样生效。

## 7. 这一批不做

多台设备各用一份 WireGuard 配置；端点用 `.local` 名字；UDP / DNS 的显示；iPhone 的 WebSocket 走 SOCKS（用 WireGuard 就不需要了）；本机用系统网络扩展抓全部 TCP。自动代理（PAC）不动，仍在配置页的「高级」里。

## 8. 做完的标准

和 `TOOLS.md` §9 相同（测试全过、`make build` 过、xcstrings 校验、不安装、不改系统代理、不按名字杀进程、临时构建放 `*.noindex`、只做本地提交），另加：

1. **真引擎验证**（端口用 196xx 一带，别用 9090–9092 和 51820，用户的 Baobox 可能正在用）：`regular` + `socks5` + `wireguard` 三种模式同时开；密钥文件被原样采用、App 拼的配置与引擎打印的一致；`record` / `lan_proxy` / `mac_tcp` 指令与 `mode: none` 的效果；经 SOCKS 的原始 TCP 产生 `tcp_*` 事件并被 Swift 侧正确读出；系统代理控制器按「HTTP、SOCKS 各自可选」被调用（用桩记录调用，不真改）。
2. **界面渲染自查**（渲染探针 `scratchpad/opus-tools/ui.noindex/build2.sh` + `main2.swift` 可以接着用）：配置页（各开关开 / 关两态、WireGuard 开着时的二维码）、HTTP 包页的新工具条、TCP 包页（列表 + 十六进制 / 文本详情）、暂停状态、900 宽下不挤掉任何控件。中英文各一套。
3. **MCP**：对着跑起来的服务把每个新工具调一遍，`set_config` 逐项对照界面状态。

5. 汇报里单列「要用户在真机上试的」：WireGuard 扫码（Android 已通，iPhone 没试）、经隧道装证书、TCP 包里能否看到手机的连接。
