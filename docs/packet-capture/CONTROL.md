## 0. 用户要的是什么（原话）

- 「直接在首页放几个功能，不需要考虑现在的什么模拟器什么的」：1 配置本机，有三个开关 http / websocket / tcp；2 固定 IP 然后展示出来，用于其他设备手动配置；3 WireGuard App，直接展示一个二维码；4 配置证书，有个开关，启动后展示二维码和内网地址。
- 「上方不需要区分什么我的设备 / 其他设备了」；每张卡片「最上方有一个开关，然后下边有不同的开关」。
- 「最上方这里有三个 tab，一个配置，一个 http 包，一个 tcp 包，支持同时抓取」。WebSocket 不拆成单独的 tab（留在 HTTP 包里，加一个筛选）。第二个标签页后来改名「HTTP / WebSocket 包」（英文「HTTP / WebSocket」），因为 WebSocket 也在这一页里看。
- 后来追加：TCP 包页要能认出连接跑的是什么协议（§4.3）；TCP 是字节流，详情默认按连续的流显示，不按读到的段（§4.2）。
- 「模拟器、终端、Android USB 这几个排在后边吧」。
- 「mcp 需要支持配置 + 查看包，支持所有的配置」。
- 之前定的也都还算数：要有暂停；WireGuard 是手机的默认接法，端点用 IP；本机的 TCP 只抓得到走系统 SOCKS 的程序（用户已接受，开关旁边写明）。

## 1. 窗口结构

```
[ 配置 ] [ HTTP / WebSocket 包 128 ] [ TCP 包 5 ]        ● 运行中 192.168.0.9:9090   [⏸ 暂停] [停止全部]
───────────────────────────────────────────────────────────────────────────────────────────────
（当前标签页的内容）
```

- 三个标签页在窗口内容区最上面一行（一条自己的标签条，不改系统标题栏）。标签上带数量。窗口窄到放不下时先收掉右边状态里的地址文字，标签名不截断（900 宽下中英文都放得下，实测）。
- 右边是全局状态和两个全局按钮：
  - **暂停 / 继续**：对 HTTP 和 TCP 同时生效；只在引擎运行时可用；不记住，引擎每次启动都从「记录中」开始。
  - **停止全部**：把四张卡片的总开关全部关掉（引擎停、系统代理还原）。只在引擎运行时显示。
- 不再有「开始 / 停止」按钮、不再有「这台 Mac / 其他设备」两个开关、不再有「设备设置」面板 —— 都由「配置」页的卡片取代。
- 暂停中，标签条下面多一条提示「已暂停：新的连接照常通过，只是不记录」和一个「继续」；状态写「已暂停」（橙点）。
- 打开窗口时：引擎在跑就停在「HTTP / WebSocket 包」，否则停在「配置」。**打开卡片开关不自动切标签页**（用户在配置页上通常要连着开几个）。

## 2. 「配置」页

│   HTTP / HTTPS          [开关]   │  │   主机 192.168.0.9  [复制]         │
│   WebSocket             [开关]   │  │   端口 9090         [复制]         │

┌ WireGuard ────────────── [总开关] ┐  ┌ 证书 ──────────────────────────────┐
│ 手机装 WireGuard App，扫码         │  │ 这台 Mac：已信任 / [安装并信任]      │
│  ┌──────┐ 端点 192.168.0.9:51820  │  │ 解密 HTTPS        [开关]  范围…    │
│  │二维码│ [复制配置]              │  │ 给其他设备装证书  [总开关]           │
│  └──────┘                         │  │  ┌──────┐ http://192.168.0.9:9091/ │
└───────────────────────────────────┘  └──┴──────┴─────────────────────────┘
┌ 模拟器 ─────────┐ ┌ 终端 / 脚本 ────┐ ┌ Android USB ────┐

### 2.1 引擎什么时候跑

- 四个总开关（本机、手动代理、WireGuard、给其他设备装证书）**任意一个开着，引擎就在跑；全关就停**。次要卡片里的操作（开终端、设模拟器）需要引擎时自己把它起起来（只起引擎，现有的 `ensureEngine`），之后由「停止全部」停。
- **总开关不跨启动保存**：App 启动时四个都是关的（Baobox 是开机自启的菜单栏 App，不能一启动就改系统代理、开监听）。子开关和各种取值保存。
- 引擎的监听组合由开关决定（`Logic/EngineLaunch.swift` 的 `EngineListeners`），变了就重启引擎一次（约 1 秒，列表不丢、暂停照旧；实测打开「手动代理」再开「给其他设备装证书」时引擎 pid 不变）：
  - HTTP 代理：`regular@<地址>:<端口>`，「手动代理」或「给其他设备装证书」开着时听 `0.0.0.0`，否则 `127.0.0.1`。
  - SOCKS：`socks5@127.0.0.1:<端口+2>`，照旧总开着、只听本机。
  - WireGuard：`wireguard:<supportDir>/wireguard.json@<WG 端口>`，「WireGuard」开着才加。
- 「给其他设备装证书」开着、「手动代理」关着时，引擎也听局域网（配置页的证书检测要连代理端口），但**局域网设备拿它当代理用要被拒**：桥加一个状态 `lan_proxy`（指令 `{"cmd":"lan_proxy","on":bool}`，启动时用选项给初值），为假时非回环、非隧道来源的普通请求一律 403（CONNECT 也拒；不发 `device` 事件，页面写「手动代理没有打开」）；发给引擎自己的、发给配置页的、证书检测照常；`check.baobox.invalid` 照常应答，但这时不顺带报待放行设备（反正它也用不了代理）。
- 「给其他设备装证书」开关只改桥的配置页端口（指令 `{"cmd":"page_port","port":N}`，0 = 没开；启动时用选项 `baobox_page_port` 给初值）：监听组合没变时不为它重启引擎。
- 桥另收一个选项 `baobox_lan_ip`（Mac 的局域网 IP）：隧道里的手机访问 Mac 用的是这个地址，桥据此认出「发给这台 Mac 自己的」（配置页、证书检测、代理地址）。
- 引擎起不来、意外退出、启动超时（状态变成 `failed`）：四个开关全部复位、系统代理还原、配置页关掉，原因显示在顶上的提示条。

### 2.2 本机

总开关 = 现在的「抓这台 Mac」（走 `startMac` / `stopMac` 那套，证书没信任时照旧弹系统验证）。三个子开关（总开关关着时变灰但保留取值）：

| 子开关 | 键 | 默认 | 作用 |
|---|---|---|---|
| HTTP / HTTPS | `netcapture.mac.http` | 开 | 系统的 HTTP、HTTPS 代理指向引擎 |
| WebSocket | `netcapture.mac.websocket` | 开 | 记录 WebSocket 消息；需要系统 SOCKS 代理（苹果的网络库只让 WebSocket 走 SOCKS） |
| TCP | `netcapture.mac.tcp` | 关 | 经 SOCKS 进来的、不是 HTTP 的 TCP 连接记进「TCP 包」。旁边一行小字：只有走系统 SOCKS 代理的程序抓得到 |

- 系统 SOCKS 代理：**本机总开关开，且 WebSocket 或 TCP 任一开着**才设；否则不碰。`SystemProxyController.apply(httpPort:socksPort:)`：HTTP（含 HTTPS）、SOCKS 两组各自可选，为 nil 的那组还原成开启前的样子，两个都是 nil 等于整体还原；抓包中任一子开关变化就重新应用。「开启前的快照」只在没有快照时拍一次，重新应用时不会把我们自己设的状态当成原状态存下来。改系统代理的调用在一条串行队列上，先开后关的顺序不会乱。
- 第一次打开、证书还没被这台 Mac 信任时，卡片上多一行小字「第一次打开要信任 Baobox 的证书，系统会弹验证框」。
- 经 SOCKS、非 443 端口的 **TLS** 连接照旧原样放行、不记录（现有规则，不改：解开它们等于看邮件之类的私有协议）。

### 2.3 手动代理

- 总开关是运行期状态（见 §2.1 不跨启动），只在 `NetCaptureSession` 里，不存 UserDefaults；方案草稿里的键名 `netcapture.lan.proxy` 没有用上（四个总开关都不存）。
- 显示主机和端口，各带一个复制按钮；一句话：Mac 的 IP 变了要重新填。
- 新设备第一次连上来仍要「允许」：待放行的设备列在这张卡片里（允许 / 拒绝），现在窗口顶上的提示条和通知也留着。
- iPhone 想用描述文件一键配手动代理，需要 Wi-Fi 名称：卡片里一个可选的输入框（现有的 `netcapture.wifiName`），旁边一行小字说明用途。

### 2.4 WireGuard

总开关开着时卡片上直接显示二维码；关着时显示占位（「打开后显示二维码」），不显示密钥相关的任何东西。

**已经在用户的 vivo 手机（Android）上验证过**（2026-11-21，临时引擎 `--mode wireguard:<密钥文件>@51820` + 桥 + 探针脚本，约 9 分钟）：920 条连接、631 次 DNS 查询进来，无报错；微信的 `mmtls` 请求、输入法的 WebSocket 握手、5 条原始 TCP 这些不认代理的流量都到了；HTTPS 大多没解密（手机没装当前证书 + App 不信任用户证书），握手失败后自动放行。隧道里客户端地址是 `10.0.0.1`，DNS 是 `10.0.0.53`。**iPhone 没试过。**

- 密钥文件 `<supportDir>/wireguard.json`，格式是引擎自己的：`{"server_key": <base64 32 字节>, "client_key": <base64 32 字节>}`（Curve25519 私钥）。没有就由 Baobox 生成（权限 600），这样没起过引擎也能出二维码；引擎读到已有的就用它（要实测它不会改写）。已验证：CryptoKit `Curve25519.KeyAgreement.PrivateKey(rawRepresentation:)` 从 `server_key` 算出的公钥与引擎打印的客户端配置一致。
- 客户端配置（二维码的内容，也是「复制配置」的内容）：

  ```
  [Interface]
  PrivateKey = <client_key>
  Address = 10.0.0.1/32
  DNS = 10.0.0.53

  [Peer]
  PublicKey = <server_key 的公钥>
  AllowedIPs = 0.0.0.0/0
  Endpoint = <Mac 的局域网 IP>:<端口>
  ```

- 端点用 IP（用户的决定）。卡片上一句话：Mac 的 IP 变了要重新扫码，或在 WireGuard App 里改端点；Baobox 没开着这个开关时隧道不通，手机会上不了网，记得在 App 里关隧道。
- 端口 `netcapture.wireguardPort`，默认 51820（UDP），设置页可改。设置页另有「重新生成 WireGuard 密钥」（确认框写明扫过的隧道会失效）。
- 隧道进来的设备**不走「允许」**：有密钥才连得上。桥按接入的监听认（`proxy_mode` 是 `wireguard`），不按地址段认 —— 家里的 Wi-Fi 也可能是 `10.0.0.x`，按地址认会把这样的局域网设备误放行。设备栏里 `10.0.0.1` 默认叫「WireGuard 设备」。
- 一份配置 = 一个对端，同一时间一台设备。多设备不在这一版。
- 纯逻辑在 `Logic/WireGuardConfig.swift`（密钥文件读写与生成、公钥推导、配置文本），有单元测试（固定私钥对照已知公钥、文本逐行对照）。
- 桥：隧道里的 UDP、DNS 原样通过，不要拦；手机经隧道访问 `http://<Mac 的 IP>:<配置页端口>/` 要到得了配置页且不进列表 —— 桥收 `baobox_lan_ip`，`is_this_machine` 把 Mac 的局域网 IP 也算作「这台机器」（经代理以本机身份打开、按 Mac 的 IP 访问配置页，已实测不进列表；经真隧道没测，见 `TECH_DESIGN.md` §1.v）。

### 2.5 证书

三样东西：

1. **这台 Mac 的信任状态**：已信任 / 「安装并信任」按钮（现有的 `session.installCert()`）。
2. **解密 HTTPS** 开关（`netcapture.decryptHTTPS`，默认开）+「范围…」（打开设置页的抓包那一栏）。关 = 桥的解密范围用新的 `mode: "none"`：`tls_clienthello` 里一律 `ignore_connection`，`tls` 事件的 reason 用 `decrypt_off`，列表里这种行的说明和「握手失败」区分开。连到引擎自己的 TLS（配置页的证书检测：直连代理端口时还没有目的地址；经隧道时目的地是 Mac 的 IP + 引擎的端口）不放行，否则证书检测会跟着失效。
3. **给其他设备装证书** 总开关：开 = 配置页服务（`ConfigPageServer`）开着，卡片上显示二维码和地址（带扫码即放行的口令，现有的 `landingPageURL`）；关 = 配置页服务关。

配置页（手机浏览器看到的）跟着变：请求是经隧道来的时，不显示配代理 / 关代理，顶上写「已通过 WireGuard 连接」，只留装证书；「手动代理」没开时同样不显示配代理那几步，顶上写「这里只装证书：Mac 上没有打开『手动代理』」。是不是经隧道来的，看桥写的 `X-Baobox-Via: wireguard`（按接入的监听判断；不是隧道来的请求桥会把这个头删掉，配置页也只在对端是这台 Mac 时认它），不看 `X-Baobox-Client` 是不是 `10.0.0.x`（理由同上）。状态清单：经代理的是「证书已信任 / 代理已生效 / Mac 已允许这台设备」；经隧道的是「证书已信任」+ 一行写死已打勾的「已通过 WireGuard 连接」；只装证书的只有证书一行。

## 4. 「TCP 包」页

### 4.1 记什么

引擎当成原始 TCP 处理的连接（mitmproxy 的 tcp flow）：不是 HTTP、也不是能解成 HTTP 的 TLS。来源有两种：手机经 WireGuard 过来的；本机经 SOCKS 过来的（要开「本机 → TCP」）。**被放行的 TLS（握手失败、不在解密范围、关了解密）不在这里**，它们仍然是「HTTP / WebSocket 包」里的「TLS」行（被放行的连接引擎不建 tcp flow，钩子根本不触发）。UDP、DNS 不显示。经手动代理的局域网设备用 CONNECT 走原始 TCP 时也会进来（来源不是回环，不受「本机 → TCP」管）。

桥的新事件（钩子 `tcp_start` / `tcp_message` / `tcp_end` / `tcp_error`，探针脚本 `scratchpad/wgtrial/wgprobe.py` 可参考）：

```
{"event":"tcp_open","id","client","host","port","sni","ts"}
{"event":"tcp_data","id","from_client":bool,"size":N,"data":"<base64>","truncated":bool,"ts"}
{"event":"tcp_close","id","error":null|"…","ts"}
```

- 每条消息的 `data` 最多带 16 KB（超过的带前 16 KB，`truncated: true`）；每条连接累计超过正文上限（现有的 `baobox_body_cap`）后只报 `size`、不带 `data`。
- 引擎会把一条 tcp flow 的所有消息一直留到连接结束；桥每收到一条就把之前的删掉（引擎转发用的是它自己手里的引用，进程里没有别人读旧消息），长连接不会越攒越多。
- 暂停时不发（规则同 HTTP：`tcp_open` 没发过的连接，后面的 `tcp_data` / `tcp_close` 也不发）。
- 「本机 → TCP」关着时，来源是回环的 tcp 连接不发事件（指令 `{"cmd":"mac_tcp","on":bool}`，启动时给初值）。隧道来的总是发。

### 4.2 界面

两栏：左边连接列表，右边详情。

- 列表一行两层：上面「目标（有 SNI 显示域名，否则 IP）`:端口` + 协议」，下面「开始时间 · 设备」；右边「状态（进行中 / 已关闭 / 出错）」，下面「时长 ↑ 字节 ↓ 字节」。新的在上。原来写的是一行多列的表格，实测 900 宽下八列放不下（每列表格自带约 20pt 的边距），挤掉的正好是时长和字节数，所以改成两层，字段一个不少。
- 协议放在目标后面，是一个小标签：认出来的正常色；只是按端口猜的带问号、次要色；认不出写「未知」。
- 工具条：清空、搜索（目标地址 / 端口）、设备筛选、协议筛选（菜单里是当前列表里出现过的协议和「未知」）、右边「显示 N / 共 M 条连接」。
- 详情：概览（目标、设备、协议（按端口猜的写「按端口推测」）、起止时间、时长、收发字节、读到的段数、出错原因）+ 数据。
- **数据默认按连续的流显示**：TCP 是字节流，引擎报上来的每条 `tcp_data` 只是「这一次读到的那一段」，边界是任意的（一条应用层消息可能被拆成几段，几条也可能粘在一段里）。所以默认把相邻、同方向的段合成一块（一问一答的交替自然分开），每块标方向、总字节数、开始时间（跨了时间的写「+N ms」）、几段；十六进制的偏移按**该方向的累计偏移**连续编号，不是每块从 0 开始。
- 「按读到的分段显示」（勾选框）：看原始的每一段（调试时序用）。偏移照样按方向累计。
- 页面上一句说明：分段的边界是读取时的边界，不代表一条完整的应用层消息。
- 没保存的部分（超过 16 KB 的那一段后面、超过正文上限之后的）在流里用一行占位「此处 N 字节未保存（偏移 …）」，偏移照样往前走，后面的偏移对得上。
- 「十六进制 / 文本」切换：默认跟着协议走 —— 文本类协议（SMTP、IMAP、POP3、FTP、XMPP、Redis、SSH 的版本行）默认文本，其余（含未知）默认十六进制，用户可以手动切。十六进制一行 16 字节，不折行（放不下横着滚）；文本模式里控制字符和解不开的字节都显示成 `·`。每块可复制、整条可「复制全部」（复制不受下面的显示上限限制）。
- 一块最多显示 64 KB（后面一行说「这一块还有 N 字节没显示，复制可以拿到全部」）；一条连接最多留前 2000 段，之后的只计数、计字节（详情底下写明）。
- 数据模型放一个新的 `TCPStore`（上限条数和 `FlowStore` 用同一个设置），纯逻辑部分进 `Logic/` 并有测试：`TCPPayload`（十六进制排版、文本判定、文本显示）、`TCPLog`（连接、段、按方向攒前缀、合块 `TCPStream`）、`TCPProtocol`（§4.3）。

### 4.3 协议识别（2026-11-21 追加）

只做「认出是什么协议并标出来」，不做各协议的逐包解析。纯逻辑在 `Logic/TCPProtocol.swift`，有单元测试（每种协议至少一条认得出的样本、一条相近但不该认的样本）。

**输入**：目标端口、SNI、两个方向各自**累计**的前 64 字节、客户端累计发了多少字节、谁先说的话（客户端 / 服务器）。**输出**：协议名 + 是不是按端口猜的，或 nil（界面显示「未知」）。

**怎么认**（特征写得保守：宁可认不出，不要认错）：

1. 先看内容特征：
   - `SSH-<数字>.` 开头（任一方向）→ SSH
   - 客户端首包是 MQTT 的 CONNECT：首字节 `0x10`，剩余长度（变长编码）≥ 10，后面是协议名 `MQTT` 或 `MQIsdp` → MQTT
   - `AMQP` + `0x00` → AMQP
   - 服务器首包是 MySQL 握手：3 字节长度（20–1024）+ 序号 0 + 协议版本 `0x0a` + 以 0 结尾、数字开头的可打印版本串 → MySQL
   - 客户端首包是 PostgreSQL 的启动报文（长度 9–10000 + `0x00030000`）或 SSLRequest（长度正好 8 + `0x04d2162f`）→ PostgreSQL
   - Redis：客户端首包 `*<数字>\r\n$<数字>`；或客户端先说话且是 `PING\r\n` / `AUTH <…>` → Redis。只凭首字节是 `*` 不算
   - MongoDB：16 字节消息头，opCode 2013（OP_MSG）或 2004（OP_QUERY），responseTo 为 0，长度合理 → MongoDB
   - 服务器首包 `220 ` / `220-` 开头且含 `SMTP` → SMTP，含 `FTP` → FTP；`* OK` → IMAP；`+OK` 且**服务器先说话** → POP3（Redis 回 `+OK` 时是客户端先说话，靠这个分开）
   - `<stream:stream` 开头，或 `<?xml` 开头且后面跟着 `<stream` → XMPP（只有 `<?xml` 的不算，SOAP 之类也这么开头）
   - `\x13BitTorrent protocol` → BitTorrent
   - 客户端首包 `0x16 0xf1 0x04` → mmtls（微信；2026-11-21 试验时在用户手机上实际看到的首包 `16f10400…`）
   - `0x16 0x03 0x00–0x04` 且第 6 字节是 `0x01`（ClientHello）→ TLS（正常情况下 TLS 不会出现在这一页，出现了就如实标）
   - RTMP：客户端首字节 `0x03`，且客户端累计已发 ≥ 1537 字节（C0 + C1），服务器回话的话首字节也是 `0x03` → RTMP。原写法是「首包长度 ≥ 1537」，但识别是按累计前缀做的（不按段），所以换成累计字节数
   - DNS over TCP：端口 53，前两个字节是后面这条消息的长度（≥ 12），头里问题数 1–16，且这条消息已经到齐 → DNS
   - SNI 是 `mtalk.google.com`（或其子域）→ FCM（解开过的 TLS 才有 SNI）
2. 内容认不出时按端口给弱提示，名字后面带问号：22 SSH?，25/465/587 SMTP?，110/995 POP3?，143/993 IMAP?，1883/8883 MQTT?，3306 MySQL?，5432 PostgreSQL?，6379 Redis?，27017 MongoDB?，5222/5223 XMPP?，5228–5230 FCM?，5671/5672 AMQP?，1935 RTMP?。
3. 都不中 → nil。

**什么时候认**：`tcp_open` 时只有端口和 SNI，先给端口提示。之后**按累计的前缀认，不按第一段**：每个方向各攒最多 64 字节（来一段就接上，只接连续的字节，攒满或连接关闭为止），每次前缀变长就重新认一次（RTMP 另在客户端累计字节数刚过 1537 时认一次）；认出确定的协议后不再认、不再变。这样特征被拆在两段里（比如第一次只读到 2 个字节）也认得出。测试里同一份首包按「一整段」「1 字节 + 其余」「和后续数据粘在一起」三种喂法，结果相同。

**MCP**：`list_tcp_connections` / `get_tcp_connection` 的返回里带协议名和它是不是按端口猜的；`list_tcp_connections` 可按协议过滤。

## 5. 暂停

桥指令 `{"cmd":"record","on":bool}`；初值在启动引擎时用选项 `baobox_record` 给（原写法是「每次引擎就绪发一遍」，改成选项是为了就绪和指令之间没有空档：开关引起的重启发生在暂停中时，第一条请求也不会漏记）。因为不记住，新启动时是 `true`，但开关引起的引擎重启保持暂停状态。只在引擎运行时可用。

- HTTP：`on` 为假时不发 `request`；发过的 flow 记 `flow.metadata["baobox_rec"] = True`，`response` / `error` / `ws` 只对带标记的发（暂停前发出的请求照常补全，暂停期间的不会恢复后冒出半条；暂停前就连着的 WebSocket 在暂停中照常记消息）。`tls` 行暂停时不发，也不记成「报过了」，恢复后再遇到同一个域名还会补一行。
- TCP：同理，见 §4.1。
- `device`、`running`、`replay_failed` 照常；Mock、设备准入、重发不受影响（重发是用户主动点的，暂停时也照发照记）。

## 6. MCP：配置 + 看包，覆盖全部配置

现有工具保留（`list_flows`、`get_flow`、`search_flows`、`latest_flows`、`clear_flows`、`list_devices`、`capture_status`；`start_capture` = 打开本机（证书没信任时只起引擎，不弹验证，现有规则），`stop_capture` = 停止全部；`capture_status` 加上暂停与否和 TCP 连接数）。工具说明里提到 HTTP 那一页时叫「HTTP / WebSocket tab」。新增：

| 工具 | 作用 |
|---|---|
| `get_config` | 返回全部开关和取值（JSON）：四张卡片的总开关与子开关、暂停、解密开关与范围、各端口、正文上限、条数上限、停止时是否清空、Wi-Fi 名称、证书是否受信任、引擎状态，以及代理地址、WireGuard 端点、配置页地址、待放行设备、脱敏开关 |
| `set_config` | 改上面任意几项（没给的不动），效果和在界面上拨一样。需要系统验证框的动作（信任证书）不做：证书没受信时 `mac: true` 不改，返回 `needs_user_in_window` 说明要用户在界面上点。等开关落定（本机要先查证书、WireGuard 要先读密钥）、引擎起来或重启完再回复，回复里带改了什么、改后的全部配置；未知键、只读键、取值不对的放进 `errors`，其余照改 |
| `get_wireguard_config` | 返回客户端配置文本（里面有隧道私钥；MCP 只听本机，说明里写清楚） |
| `list_tcp_connections` / `get_tcp_connection` / `clear_tcp` | TCP 包。`list_tcp_connections` 按设备、协议、目标过滤。`get_tcp_connection` 默认返回合并后的块（方向、按方向累计的偏移、长度），`segments: true` 要原始分段；`limit`（块 / 段数）、`format`（hex / text / auto，默认 auto：像文本的块给文本，否则十六进制 —— 用的就是 `TCPPayload` 的文本判定）。每块最多带 8 KB、整个回复最多约 96 KB |
| `list_mock_rules` / `set_mock_rule` / `delete_mock_rule` | Mock 规则（新增、修改、启停、删除） |
| `replay_flow` | 重发一条（可带改动：方法、URL、请求头、正文） |
| `allow_device` / `deny_device` | 待放行设备 |

`set_config` 改到端口、WireGuard 端口、正文上限这类「下次启动才生效」的值时，返回里写明（`applies_next_engine_start`）。脱敏开关（`mcpRedactAuth`）对新工具同样生效（Mock 规则的请求头）；`get_tcp_connection` 的原始数据没法按头脱敏，工具说明里写了。脱敏开关本身在 MCP 里只读：让 AI 自己关掉脱敏就失去了意义。

做的时候发现本地 MCP 服务本来就不应答：每条连接的会话对象建出来就被释放了（接收回调里是 `[weak self]`，编译器早有警告），请求被接下来以后一直挂着。已修。

## 7. 这一批不做

多台设备各用一份 WireGuard 配置；端点用 `.local` 名字；UDP / DNS 的显示；iPhone 的 WebSocket 走 SOCKS（用 WireGuard 就不需要了）；本机用系统网络扩展抓全部 TCP。自动代理（PAC）不动，仍在配置页的「高级」里。

**TCP 应用层消息的拆分不做**：按协议把字节流拆成一条条消息（长度头、分隔符……）要逐个协议写解析器，不在这一批。这一批只认协议（§4.3）、按连续的流显示（§4.2）。以后要做可以从格式简单的开始：MQTT（固定头 + 变长剩余长度）、Redis（RESP，按 `\r\n` 和长度前缀）。

## 9. 实现时和方案不一样的地方（2026-11-21）

正文已按实际做法改过，这里集中列一遍，复核时看这一节即可。

| # | 方案原写法 | 实际做法 | 为什么 |
|---|---|---|---|
| 1 | 隧道设备启动时放进 `baobox_allowed` | 桥按接入的监听（`proxy_mode == wireguard`）放行 | 家里的 Wi-Fi 也可能是 `10.0.0.x`，按地址放行会误放局域网设备 |
| 2 | 配置页按 `X-Baobox-Client` 是不是 `10.0.0.x` 认隧道 | 桥另写 `X-Baobox-Via: wireguard`（非隧道请求删掉这个头） | 同上 |
| 3 | `record` 每次引擎就绪发一遍 | 启动时用选项 `baobox_record` 给初值，之后变了发指令 | 就绪和指令之间没有空档，暂停中重启不漏记 |
| 4 | 没写 | 新指令 `page_port`（+ 选项 `baobox_page_port` 给初值） | 「给其他设备装证书」开关变了、监听组合没变时不用重启引擎 |
| 5 | 「必要时」把 Mac 的 IP 传给桥 | 加了选项 `baobox_lan_ip` | 没有隧道客户端可测，按 IP 认「这台机器」最稳 |
| 6 | `check.baobox.invalid` 照常 | 照常应答，但「手动代理」关着时不报待放行设备 | 和「拒绝时不发 `device` 事件」一致 |
| 7 | 手动代理总开关键 `netcapture.lan.proxy` | 不存 UserDefaults，四个总开关都是会话里的运行期状态 | §2.1 总开关不跨启动 |
| 8 | Android USB 没写开关要求 | 要「手动代理」开着，没开只提示 | 手机经 Wi-Fi 拿 Mac 当代理；和模拟器卡片「不替用户开」一致 |
| 9 | TCP 列表一行多列 | 一行两层的列表，字段不少，协议是目标后面的小标签 | 900 宽下八列放不下，挤掉的是时长和字节数 |
| 10 | RTMP「首包长度 ≥ 1537」 | 客户端累计 ≥ 1537 字节（+ 服务器首字节 0x03） | 识别按累计前缀做，不按段 |
| 11 | DNS「前两个字节是后续长度」 | 再加问题数 1–16、整条消息到齐 | 保守，避免把 53 端口上随便什么都认成 DNS |
| 12 | XMPP `<?xml` 即算 | `<?xml` 后面还要跟着 `<stream` | `<?xml` 开头的还有 SOAP 等 |
| 13 | 输入里没有「谁先说话」 | 加了 `firstSpeaker` | 分开 POP3（服务器先 `+OK`）和 Redis（客户端先 `AUTH`、服务器回 `+OK`） |
| 14 | SNI 作为输入 | 用在 FCM：SNI 是 `mtalk.google.com` 算确定的 FCM | 其余协议靠内容就够 |
| 15 | 文本模式 | 控制字符和解不开的字节都显示成 `·` | SSH 版本行之后是密文，不然满屏替换符 |
| 16 | 没写 | 一条连接留前 2000 段，一块最多显示 64 KB；MCP 每块 8 KB、整个回复约 96 KB | 内存和渲染有上限 |
| 17 | 没写 | 桥收到一条 TCP 消息就删掉引擎里攒的旧消息 | 引擎会把整条连接的消息留到结束，长连接越攒越多 |
| 18 | 没写 | 暂停时标签条下多一条提示和「继续」；本机卡片在证书没信任时多一行说明 | 一眼看清暂停是什么意思；第一次打开会弹验证框，先说一声 |
| 19 | 没写 | 修了 MCP 服务从不应答的老问题 | 见 §6 |
