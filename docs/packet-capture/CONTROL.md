# 抓包：开关重整 + WireGuard 接入（方案）

> 2026-11-21 定。实现者先读 `TECH_DESIGN.md` §1（验证记录，尤其 §1.w 工具条、§1.x–§1.z 手机配置）和 `TOOLS.md` §9（做完的标准与坑）。
> 这份文档是用户逐条确认过的做法，**照文档实现**；实现中发现走不通的地方，就地改文档并在汇报里写明。

## 0. 为什么改

用户在真机上用下来的两类问题：

1. 「开始 / 停止」一个按钮管了两件事（代理服务开不开、请求记不记），没有暂停；一停代理，配着手动代理的手机就断网。协议层面（HTTPS 解密、WebSocket）也没有快捷开关。
2. 手机接入太绕：Wi-Fi 代理要装描述文件（每次都要锁屏密码、常常还要 Wi-Fi 密码），关代理又要装一个；iPhone 的 WebSocket、不认系统代理的 App、原始 TCP 都抓不到。

用户的决定（原话）：「把启动代理服务器做成一个明确的开关」「开始抓包后只有停止，没有暂停」；WebSocket「开启时如果这台设备是选中的就自动配置 socks 代理，没开就不要开，两个开关单独弄，不要再多一个选项」；WireGuard「多一个 app 而已，会方便很多」「把这种方式设置为默认方式」，端点用 IP（「不用了，还是 ip 吧」）。

## 1. 开关模型

| 开关 | 在哪 | 存哪 | 作用 |
|---|---|---|---|
| **代理** | 工具条最左，取代「开始 / 停止」 | 不存 | 引擎开不开。开 = 现在的 `session.start()`；关 = `session.stopAll()`。**打开即开始记录** |
| **暂停 / 继续** | 工具条，紧挨「代理」，代理开着才可用 | 不存（每次打开代理都从「记录中」开始） | 只管请求进不进列表。暂停时流量照常、解密照常、Mock 照常、设备放行照常 |
| **这台 Mac** | 工具条（已有） | `netcapture.lastMacCapture` | 系统代理指过来 / 还原 |
| **其他设备** | 工具条（已有） | `netcapture.phoneEnabled` | 引擎听局域网、开配置页、开 WireGuard（§2） |
| **解密 HTTPS** | 控制面板 | `netcapture.decryptHTTPS`（Bool，默认 true） | 关 = 所有 TLS 原样放行，只显示域名。旁边「范围…」跳到设置页的解密范围 |
| **WebSocket** | 控制面板 | `netcapture.captureWebSocket`（Bool，默认 true） | 关 = 不记录 WebSocket 消息，**也不设系统 SOCKS 代理** |
| 本地 MCP 服务 | 控制面板（「⋯」里现有的那个也留着） | 现有 | 现有 |

不做开关的：配置页服务（跟随「其他设备」）、SOCKS 端口（跟随「WebSocket && 这台 Mac」）、TCP（见 §3）。

### 1.1 代理开关与暂停

- 工具条：`[代理 开关] [⏸ 暂停 | ▶ 继续]  抓：[这台 Mac] [其他设备] …`。「代理」做成看得出开 / 关两态的按钮（开着是强调色、写「代理：开」，关着写「代理：关」），不要再出现「开始」「停止」这两个词。
- 状态条：运行中 / 已暂停记录 / 已停止。
- 暂停的实现在桥里（不在 Swift 里丢事件，省得引擎白编码正文）：新指令 `{"cmd":"record","on":false}`。桥的规则：
  - `request` 事件：`on` 为假时不发；发了的在 `flow.metadata["baobox_rec"] = True`。
  - `response` / `error` / `ws`：只对带 `baobox_rec` 的 flow 发（这样暂停前发出的请求，响应回来照常补全；暂停期间的请求恢复后不会冒出半条）。
  - `tls`（未解密的那种行）：暂停时不发。`device`、`running`、`replay_failed` 照常。
  - Mock、设备准入、发给自己的请求这些逻辑不受影响。
- 引擎每次就绪都按当前状态发一遍（和规则、解密范围一样）；因为不记住暂停，新启动时总是 `on: true`，但「其他设备」开关引起的引擎重启要保持暂停状态。
- 重发（`replay`）在暂停时照发、照记（用户主动点的）。

### 1.2 解密 HTTPS

- 桥的解密范围多一种 `mode: "none"`：`tls_clienthello` 里一律 `ignore_connection`，`tls` 事件的 reason 用 `decrypt_off`。Swift 侧 `DecryptScope.from(…)` 在开关关着时给出 none；开关一变就 `applyScopeFromSettings()`。
- 列表里这种行的说明文字要和「握手失败」区分开（「已关闭解密」）。

### 1.3 WebSocket

- 关着时桥不发 `ws` 事件：指令 `{"cmd":"websocket","on":false}`，同样每次就绪发一遍。握手那一行（101）照常是一条普通请求。
- 系统 SOCKS 代理：只在「WebSocket 开 **且** 这台 Mac 开」时设。`SystemProxyController.enable(port:socksPort:)` 的 `socksPort` 改成可空，空 = 不碰 SOCKS；抓包中任一开关变化时重新应用（已保存的原状态不能被覆盖成「我们自己设的」——注意 `restore()` 依赖开启前的快照）。
- 引擎的 SOCKS 监听照旧总开着（只听本机），不必跟着开关启停。

### 1.4 控制面板

「代理」开关右边一个小的展开按钮，点开是 popover，把所有开关列全（工具条上那几个在这里也有一份，状态同步）：

```
代理服务                [开]   192.168.0.9:9090
记录                    [开]
来源
  这台 Mac              [开]
  其他设备              [关]
协议
  解密 HTTPS            [开]   范围…
  WebSocket             [开]
其他服务
  设备配置页            跟随「其他设备」   :9091
  WireGuard             跟随「其他设备」   :51820/udp
  本地 MCP 服务         [关]             :9191
```

popover 挂在工具条上（不是挂在某一档的按钮上，见 `NetCaptureWindow.swift` 里「设备设置」的做法和原因）。工具条四档收缩要重新排一遍，保证 900 宽不挤掉任何按钮（渲染探针 `scratchpad/opus-tools/ui.noindex/build2.sh` + `main2.swift` 可以直接用）。

## 2. WireGuard：其他设备的默认接入方式

### 2.1 已经验证过的（2026-11-21，用户的 vivo 手机，Android）

临时起的引擎：`--mode wireguard:<密钥文件>@51820`，桥 + 一个只打日志的探针脚本，`baobox_allowed=10.0.0.1`。手机装官方 WireGuard App 扫码、打开隧道，用了约 9 分钟：

- 通：920 条连接、631 次 DNS 查询都进来了，没有报错。
- 不认系统代理的流量抓到了：微信的 `mmtls` 明文 HTTP 请求、vivo 输入法的 WebSocket 握手、5 条原始 TCP（80 / 8080 / 8888 / 443 端口上的私有协议）。
- HTTPS 基本没解密（67 个域名握手失败后自动放行）：那台手机没装当前的证书，加上 Android 上大多数 App 不信任用户证书。隧道本身和解密无关，证书仍然要装。
- 隧道里的客户端地址是 `10.0.0.1`；DNS 是 `10.0.0.53`（引擎自己应答）。
- 密钥文件是 JSON：`{"server_key": <base64 32 字节>, "client_key": <base64 32 字节>}`。用 CryptoKit 的 `Curve25519.KeyAgreement.PrivateKey(rawRepresentation:)` 从 `server_key` 算出的公钥，和引擎打印的客户端配置里的 `PublicKey` 一致 —— 所以 **App 自己就能拼出客户端配置**，不用去读引擎的日志（`-q` 下引擎也不打印）。
- 用系统自带的二维码生成器做的码，WireGuard App 能扫。

**没验证的**：iPhone（只试了 Android）；`regular` + `socks5` + `wireguard` 三种模式同时开（TECH_DESIGN §7 记过 regular + wireguard 能同时开）；配置页经隧道访问；HTTP/3（QUIC）经隧道时的表现。实现时都要实测。

### 2.2 引擎

- 「其他设备」开着时，启动参数多一个 `--mode wireguard:<supportDir>/wireguard.json@<端口>`。端口：`netcapture.wireguardPort`，默认 51820（UDP），设置页可改。
- 密钥文件由 Baobox 自己先生成（没有就建：两把 Curve25519 私钥，按上面的 JSON 格式，权限 600）。这样引擎没启动过也能出二维码。引擎读到已有的文件就用它（要实测确认它不会改写）。
- 隧道进来的设备地址是 `10.0.0.x`：有密钥才连得上，所以**不走「允许」那一步**，启动时把 `10.0.0.1` 放进 `baobox_allowed`。左栏里它默认叫「WireGuard 设备」。
- 一份配置 = 一个对端：同一时间只支持一台设备连隧道。多台设备各自一份配置不在这一版里。
- 桥：隧道里的原始 TCP / UDP / DNS 不经过 HTTP 那套钩子，本来就原样通过，**不要拦**。`is_this_machine` 现在靠 `sockname` 和本机名字认「发给自己」的请求，隧道模式下 `sockname` 是什么要实测；手机经隧道访问 `http://<Mac 的 IP>:<配置页端口>/` 必须能到配置页、且不进列表（必要时加一个 `baobox_host_ips` 选项把 Mac 的 IP 传给桥）。

### 2.3 客户端配置与二维码

```
[Interface]
PrivateKey = <client_key>
Address = 10.0.0.1/32
DNS = 10.0.0.53

[Peer]
PublicKey = <server_key 的公钥>
AllowedIPs = 0.0.0.0/0
Endpoint = <Mac 的局域网 IP>:<端口>
```

- 纯逻辑放 `Logic/WireGuardConfig.swift`（密钥文件的读写与生成、公钥推导、配置文本），要有单元测试（用固定私钥对照已知公钥；文本逐行对照）。CryptoKit 在测试 target 里能不能用要确认（`BaoboxTests` 只编纯逻辑；CryptoKit 是系统库，Clipboard 那边已经在用）。
- 端点写 IP（用户的决定）。IP 变了：重新扫码，或在 WireGuard App 里改「端点」。面板上要写这句话。
- 二维码里有隧道私钥：只在本机显示，不落盘成图片。

### 2.4 界面

「设备设置」面板里 iPhone / iPad、Android 两组的主按钮改成 **「用 WireGuard 连接…」**，点开的面板：

```
┌──────────────┐  1. 手机装 WireGuard（官方 App）
│  隧道二维码   │  2. App 里「添加隧道 → 扫描二维码」，扫左边的码
│              │  3. 打开隧道开关。之后开关都在 WireGuard App 里拨
└──────────────┘  4. 要看 HTTPS 的内容：再装证书 →［显示证书二维码］
端点 192.168.0.9:51820（Mac 的 IP 变了要重新扫码，或在 App 里改端点）
Baobox 没在抓包时隧道不通，手机会上不了网，记得在 App 里关掉隧道。
                                  ［改用 Wi-Fi 代理…］［好］
```

- 「改用 Wi-Fi 代理…」= 现在的手机面板（配置页二维码 + 手动代理那套），原样保留为备选。
- 「别的电脑」那一组多一个「复制 WireGuard 配置」（桌面版 WireGuard 可以直接粘贴导入）。
- 打开这个面板和打开现在的手机面板一样，会把「其他设备」打开（`setLAN(true)`）。
- 配置页（手机浏览器看到的那个）：请求是经隧道来的（来源 `10.0.0.x`，桥在 `X-Baobox-Client` 里带着）时，不显示配代理 / 关代理那两步，顶上写「已通过 WireGuard 连接」，只留装证书（iOS 是安装 + 信任两步）。状态清单里「代理已生效」那一项在隧道下本来就会打勾，文字改成对两种方式都说得通的。
- 设置页：WireGuard 端口；「重新生成 WireGuard 密钥」（确认框写明：手机上扫过的隧道会失效，要重新扫码）。注意确认框的坑：别在确认框的按钮里取 `NSApp.keyWindow`（见 `NetCaptureSettingsView.regenerate()` 的注释）。

### 2.5 各类设备默认怎么接（用户问「模拟器 / 其他设备如何配置比较方便」）

「设备设置」面板按这张表排，每组第一个按钮是默认做法：

| 设备 | 默认做法 | 手上要做的 | 备选 | 说明 |
|---|---|---|---|---|
| iPhone / iPad | WireGuard | 装 App、扫码、开隧道；要看 HTTPS 再装证书（安装 + 信任两步） | Wi-Fi 手动代理（配置页） | 隧道下 WebSocket、不认代理的 App 也抓得到 |
| Android 手机 | WireGuard | 同上；证书在系统设置里装 | 连着 USB 调试时「USB 一键设置」（adb 设代理 + 推证书）；Wi-Fi 手动代理 | 大多数 App 不信任用户证书，HTTPS 只能看到域名 |
| iOS 模拟器 | 一键装证书 | 点一下（`simctl keychain add-root-cert`），并打开「这台 Mac」 | 无 | 模拟器没有自己的代理设置，也装不了 WireGuard，流量跟着 Mac 的系统代理走，在列表里算「本机」 |
| Android 模拟器 | adb 一键设置 | 点一下（代理指向 `10.0.2.2`、证书推进去），证书仍要在模拟器的设置里点几下装上 | 无 | 走本机回环，不需要打开「其他设备」，在列表里算「本机」 |
| 别的电脑 | 手动填代理 | 复制代理地址填进系统或浏览器，浏览器打开配置页下载并信任证书 | 复制 WireGuard 配置，导入桌面版 WireGuard（整机流量都过来，一般没必要） | |
| 这台 Mac 的终端 | 打开抓包终端 | 点一下 | 复制环境变量 | |

面板里 iOS 模拟器那一行的说明要写明「需要打开『这台 Mac』」；点「给 iOS 模拟器装证书」时如果「这台 Mac」没开，顺手提示一句（不要替用户打开——它会改系统代理）。

## 3. 这一批不做

- 原始 TCP / UDP 连接的列表和详情（隧道里它们已经在过，只是不显示）。下一批单独做，做出来默认关。
- 多台设备各用一份 WireGuard 配置；端点用 `.local` 名字。
- iPhone 的 WebSocket 走 SOCKS（用 WireGuard 就不需要了）。
- 自动代理（PAC）相关的东西不动，仍在配置页的「高级」里。

## 4. 做完的标准

和 `TOOLS.md` §9 相同（测试全过、`make build` 过、xcstrings 校验、不安装、不改系统代理、不按名字杀进程、临时构建放 `*.noindex`、只做本地提交），另加：

1. 真引擎验证：三种模式同时开；`record` / `websocket` 指令和 `mode: none` 的效果（暂停前后的请求各是什么表现）；用**桌面版或命令行的 WireGuard 客户端做不到的话**，至少用引擎确认密钥文件被原样采用、App 拼出的配置与引擎打印的一致。隧道的真机部分由用户验证，汇报里写清楚需要他试哪几步。
2. 界面渲染自查：工具条四档宽度（中英文）、控制面板、WireGuard 面板、暂停状态。
3. 文档：`TECH_DESIGN.md` §1 补验证记录；这份文档里和实际做法不一致的地方就地改掉。

注意临时引擎的端口不要用 51820 和 9090–9092（用户的 Baobox 可能正在用），用 196xx 一带。
