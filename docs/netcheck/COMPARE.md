# 网络检测 · 「IP 检测」页：列出每一步查到的，互相不一致就说「不一致」

> 2026-11-25 设计（同日按用户的第二条意见改过一版：没有「基准」）。取代 `DESIGN.md` 里「判泄露 + 两个问题的总结」的呈现方式。和 `SPEED.md` 在同一个分支上做。
> 规则照 `docs/launcher/WORKFLOW.md`。

## 背景

用户在真机上跑了第一次泄露检测，三条反馈（2026-11-25）：

1. 看到「App 能看出你的真实位置吗 —— 看不出 —— App 看到的位置是 Singapore…」，问「这里为什么显示 App 能看到位置」。结论性的句子读反了。
2. 「我觉得不要标记有没有泄漏，直接标记每一步检测出来的 ip / 国家，如果有不同的就标记为红色。」
3. （看了第一版设计「以出口 IPv4 为基准，和它不一样的标红」之后）「但是你并没有出口的正确值是什么吧？你发现有不一致的，你直接给一个结论就说不一致就行。」

所以这一页：

- 不替用户下「泄露 / 没泄露」的结论，不回答那两个问题。
- **没有哪一行是「正确值」**。程序不知道用户真正该从哪出去，它只能看到各条路查到的东西彼此对不对得上。
- 只做一件事：把每条路查到的 IP、国家、归属列出来；**对不上就给一个结论「不一致」**，并把对不上的格子标红。

## 1. 页面

窗口里这一页的名字从「泄露检测」改成 **「IP 检测」**（另一页是「测速」）。

从上到下：

1. 一行结论 + 按钮：**`一致`** 或 **`不一致`**（红色）；右边「复制报告」「立即检测」。下面小字写检测时间。「不一致」时小字里再写是哪几样对不上：`国家 · 归属 · 地址 · 时区` 里出现了的那几个。没测过时写「还没检测过」。
2. 一张表，五行，四列：

| | IP | 国家 / 地区 | 归属 |
|---|---|---|---|
| **IPv4** | `8.219.158.59` | Singapore · Singapore | Alibaba (US) Technology Co., Ltd. · AS45102 `机房` |
| **IPv6** | `2408:…` 或「没有」 | … | … |
| **DNS**（8 台） | 每个不同的「国家 + 归属」一行，前面写台数 | … | … |
| **WebRTC** | 网页拿到的公网地址，一个一行 | … | … |
| **时区** | 系统 `Asia/Singapore` | IP 所在 `Asia/Singapore` | |

3. 底部保留那句说明：「这里测的是网络层。App 有定位权限时会直接用 GPS / Wi-Fi 定位，与代理无关。」bash.ws 的结论文字不再显示。

- 行名就叫 `IPv4`、`IPv6`，不叫「出口」；没有哪一行特殊。
- **标红的是对不上的那个格子里的字**（不是整行）。行首的小圆点：这一行有红字就是红色，没有就是灰色（不用绿色对勾）；没测出来的是灰色问号，格子里写原因。
- `机房`、`VPN`、`代理`、`Tor` 是归属后面的灰色小标签（原来的 `NetCheckExitFlag`），只是信息，不标红、不影响结论。
- 地址用等宽字体，可以选中复制。

## 2. 怎么比（纯逻辑，有测试）

四样东西各自比，每一样把能比的值放在一起看：

| 比什么 | 哪些值放在一起比 | 怎么算一样 |
|---|---|---|
| **国家** | IPv4 的国家、IPv6 的国家、DNS 每一组服务器的国家、WebRTC 每个公网地址的国家 | 国家名相同（大小写不敏感、去首尾空白） |
| **归属** | IPv4 的归属、IPv6 的归属、WebRTC 每个公网地址的归属 | 同一个 ASN，或同一家云厂商的不同 ASN（沿用现有的判断）。**DNS 的归属不参加**，只列出来 |
| **地址** | IPv4 那一行的地址和 WebRTC 拿到的 IPv4 公网地址；IPv6 那一行的地址和 WebRTC 拿到的 IPv6 公网地址（两族分开比） | 完全相同 |
| **时区** | 系统时区、IP 所在的时区（取 IPv4 的；没有就取 IPv6 的） | 时区名相同 |

- 每一样里：值都一样（或只有一个值、或没有值）→ 这一样「一致」。出现了不同的值 → 这一样「不一致」。
- **结论**：四样都一致 → `一致`；任何一样不一致 → `不一致`。
- **标红哪些格子**（没有基准，所以按多数）：某一样不一致时，出现次数最多的那个值不标，其余的值所在的格子标红；**并列最多时全都标红**（比如只有两个值、一边一个：两个都红）。DNS 的一组按一个值算（不按台数加权）。
- 缺的值不参加比较，也不算不一致：没有 IPv6、某一项没测出来、回包里没有国家，都只是少一个值。
- 能比的值不足两个时，那一样算一致（没东西可比）。如果四样都因为缺值而没东西可比（比如 IPv4、IPv6 都没测出来），结论写 `没测出来，无法比较`，不写「一致」。

几条取舍的原因（写给以后改规则的人）：

- **归属也要比**：用户人在新加坡、代理出口也在新加坡时，国家永远一样。IPv4 走代理而 IPv6 或 WebRTC 走本地运营商，只有归属和地址能看出来。
- **DNS 的归属不比**：代理里用公共 DNS（Google、Cloudflare）是常态，归属和别的行不同不说明什么。
- **按多数标红只是为了指给人看「哪里不一样」**，不是说多数那边就是对的。结论只有「一致 / 不一致」。
- WebRTC 里的内网地址、mDNS 名字（`xxxx.local`）不算公网地址，不列进表里，也不另外提示。一个公网地址都没有时那一行写「网页没拿到公网地址」。
- WebRTC 拿到的地址和 IPv4 / IPv6 那一行的相同：国家、归属直接用那一行的，不另外查。不同：对这个地址再查一次归属（和查 IPv4 用同一个服务、同一套解析），查不到就只显示地址，国家和归属写「没查到」（没查到的不参加国家、归属的比较，但地址本身照样参加地址的比较）。这是这一页唯一新增的网络请求，只在地址不同时发，最多查 3 个。

## 3. 去掉的东西

- 整体结论（「没有泄露，但有能被看出来的地方」那一行）、两张总结卡片（运营商 / 真实位置）、每一行的结论句子。
- **「真实网络」整套**：窗口里「把 ASxxxx 记为真实网络」的按钮、设置页里的真实网络列表、对应的设置键和判断。旧设置键不迁移（这个功能还没发布过）。
- 纯逻辑里只为上面这些服务的类型和函数（`NetCheckVerdict`、`NetCheckReason` 里的结论、`NetCheckSummary`、`NetCheckGoal`、`NetCheckProxyHint`、`NetCheckRealNetworks` 等）：没人用了就删掉，连同它们的测试和文案 key。回包解析、ICE 候选解析、地址分类、「同一家云厂商」的判断留着。不留死代码。
- `DESIGN.md` §3 说判定规则和 `baobox_shared` 的 `netcheck.rs` 是同一套：从这一版起 Mac 端的呈现不再跟那份规格走。在 `DESIGN.md` 里写明这一点（Windows / Linux 那边要不要跟着改，另行决定，这一步不动别的仓库）。

## 4. 跟着变的地方

- **菜单**：上次结果那几行换成一行：`上次检测：一致 · 3 分钟前` / `上次检测：不一致 · 3 分钟前`。没测过：`还没检测过`。
- **复制报告**（纯文本）：第一行是结论和时间；之后每行「项目：IP · 国家 · 归属」，标红的格子后面加 `（不一致）`。
- **设置页**：去掉真实网络那一节；ipapi.is 的 key、DNS 探测个数、STUN 服务器留着。
- **快速入口命令**：`SPEED.md` §1.4 里那条「网络泄露检测」改名「IP 检测」，关键词 ip、出口、泄露、leak、vpn、dns。
- **隐私**：不变（只在点了才测，结果不落盘）；WebRTC 地址不同时多查一次归属，写进 `DESIGN.md` §2。

## 5. 文案

- 结论：`一致`、`不一致`、`没测出来，无法比较`、`还没检测过`、`检测中…`；「不一致」下面的小字：`对不上的：%@`（里面是 `国家`、`归属`、`地址`、`时区` 用顿号连起来）
- 列名：`IP`、`国家 / 地区`、`归属`；行名：`IPv4`、`IPv6`、`DNS`、`WebRTC`、`时区`
- 格子里：`没有`（没有 IPv6）、`没查到`、`没测出来：<原因>`、`网页没拿到公网地址`、`系统 %@`、`IP 所在 %@`、`%lld 台`
- 数字插值注意：ASN 一律当字符串传，不要让 `%lld` 给它加千位分隔符（真机上出现过 `AS45,102`）。
- en + zh-Hans 都要有；不再用的 key 从 `Localizable.xcstrings` 删掉。

## 7. 要渲染看的图

## 8. 测试要覆盖

四样各自的一致 / 不一致 / 缺值；多数规则（3 比 1 只红 1 个；1 比 1 两个都红；2 比 2 四个都红；DNS 一组算一个值）；归属的「同一家云厂商」；地址按族分开比；值不足两个算一致；全都缺值时是「无法比较」而不是「一致」；DNS 按「国家 + 归属」分组与台数；WebRTC 只留公网地址、和 IPv4 / IPv6 那一行相同时不另查；结论下面「对不上的」清单的内容和次序；纯文本报告的 `（不一致）` 标记；ASN 不带分隔符。

开着代理 / 关掉代理各跑一次看表里的内容；Tailscale 出口节点、只接管 TCP 的系统代理（WebRTC 的地址应该标红）；有 IPv6 的网络。

## 10. 落地记录（2026-11-25）

实现里补的细节：

- 表：行名一列 100 pt，其余三列按 IP 30%、国家 / 地区 28%、归属 42% 分（宽度取这一页外面给的，不量表自己）；窗口默认宽从 620 改成 680。窗口最小 520 时长归属名和 IPv6 地址折成两三行，不出界。
- 时区那一行：「系统 …」放在 IP 列，「IP 所在 …」放在国家 / 地区列，归属列空着。
- DNS 一组：IP 列写「N 台」，国家列只写国家（同组可能跨城市），归属列「运营方 · AS…」。行名「DNS（N 台）」，N 是总台数。
- 归属的比较键：ASN 在内置云厂商表里就用厂商名（同一家的不同 ASN 归一），否则用 `AS<号码>`；没有 ASN 的不参加比较（只显示名字）。
- 小标签（机房 / VPN / 代理 / Tor）显示在归属下面的灰色胶囊里；WebRTC 那一条借用 IPv4 / IPv6 那一行时小标签也跟着。报告里写在归属（和它的「（不一致）」）后面的方括号里。
- 报告：第一行「IP 检测：<结论> · <时间>」；不一致时第二行「对不上的：…」；空一行后每一条一行；最后是定位那句说明。
- 菜单那一行直接用结论：「上次检测：一致 / 不一致 / 没测出来，无法比较 · 3 分钟前」。
- IPv4 没测出来时，WebRTC 的地址只要和测出来的那一行（IPv6）不同就另查。
- DNS 没测出来的两种原因单独写：「bash.ws：<它的原话>」、「一台 DNS 服务器都没看到，再测一次」。
- 设置里 STUN 那一项的说明原来是「网页经它拿到的公网地址应当就是出口 IP」（带判断），改成「网页经它拿到自己的公网地址，就是表里 WebRTC 那一行」。
- bash.ws 的 `ip`（它看到的客户端）和 `conclusion` 记录不再解析。

真机跑了两次（本机直连、没开代理，约 6 秒，五项都有结果，WebRTC 的地址和 IPv4 相同）。两次结论都是**「不一致：国家」**：DNS 有两组都是 Google（AS15169），bash.ws 把一组标成 `Singapore`、另一组标成 `USA`，标红的是 `USA` 那组。这暴露了两件事，**按设计照做了，没有改规则，请设计者定**：

1. 公共 DNS 的任播节点会被 bash.ws 定位到运营方注册的国家，于是不开代理也会出「不一致」。
2. 两个服务对同一个国家的写法不同：bash.ws 写 `USA`，ipapi.is 写 `United States`。代理出口在美国、DNS 也在美国时，按「国家名相同」比会被算成两个国家。可以考虑统一成国家代码再比（要看 bash.ws 的回包里有没有代码，或者在纯逻辑里放一张常见写法的对照表）。
