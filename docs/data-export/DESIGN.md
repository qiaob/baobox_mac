# 数据导出与导入（#104）

> 状态：已实现（2026-11-10）。和设计稿不一样的地方都标在 §6。

## 1. 要解决的问题

换电脑时，手工攒下的东西带不走：文本片段、听写历史、专注与健康的提醒设置、专注历史。
整个 `~/Library/Application Support/Baobox/` 打包也不行：

- 剪贴板历史是加密的，密钥在这台 Mac 的钥匙串里（`ThisDeviceOnly`），拷到别的 Mac 上解不开；
- 里面还有几个 GB 的本地模型、几百 MB 的词典，都能重新下载，不该进备份。

## 2. 做法：一个 JSON 文件

**设置 → 通用 → 数据**：「导出个人数据…」「导入…」两个按钮，下面一行小字说明里面有什么、换电脑时导入合并；
做完一次导出 / 导入，这行小字换成结果（「已导出到「Baobox-备份-2026-11-10.json」。」「已合并。」）。

导出存一个 `Baobox-备份-2026-11-10.json`（英文界面是 `Baobox-Backup-2026-11-10.json`，保存面板选位置）：

```json
{
  "format": "baobox-export", "version": 1, "exportedAt": "…", "app": "0.0.9",
  "snippets":        [ … 文本片段：id、标题、内容、关键字、建立时间、类型（text / link）… ],
  "dictationHistory":[ … 听写历史：id、文字、时间、插入到的 App … ],
  "focusHealth":     { "items": [ … 提醒项 … ], "settings": { … 专注与健康的设置键 … } },
  "focusHistory":    [ … 专注历史（docs/focus-health/HISTORY.md §2）… ]
}
```

- 时间一律 ISO 8601（UTC，到秒）。键按字母排序、缩进排版，人能看懂。
- **片段** = 设置 → 剪贴板 → 文本片段里列的那些（文本 / 链接类的收藏，片段本来就是收藏条目，见 `docs/snippets/DESIGN.md`）。
  来源标成敏感的条目（密码管理器复制的，`isConcealed`）不导出。
- **专注与健康的设置键**只写这台 Mac 上**设过**的（UserDefaults 里有这个键、类型对、在范围里）；没设过的就是出厂值，不写。
  能进备份的 14 个键见 `BaoboxBackup.focusSettingSpecs`（出厂值、范围与 `FocusHealthSettings` 的读法一致，探针逐个核对）。
  宠物关闭时的背景**图片**是这台 Mac 上的文件路径，不进备份；背景选了「图片」的那一项也就不导出。
- **明文**：保存面板上写着「文件不加密，里面有你的片段和听写内容，请放在安全的地方。」
- 不含：剪贴板历史（除片段外）、截图、会议记录（会议库本身就是文件夹，直接拷）、API Key（钥匙串里的东西一律不出来）、
  本地模型、词典、宠物形象，以及别的模块的设置。

## 3. 导入：合并，不覆盖

选一个导出文件 → 先显示摘要，一类一行：

```
片段 12 条（新 9 条）
听写 340 条（新 120 条）
提醒 6 项（新 2 项）
专注记录 85 条（新 80 条）
专注设置：改 3 项（只改这台 Mac 上还是出厂值的）

这些关键字本机已在用，导入的片段不带关键字：;mail、;sig
```

确认「合并」后才写；全都已经在这台 Mac 上时标题是「没有新内容」，只有一个「好」。文件里没有的那一类不列。

- 片段：id 相同（和剪贴板里任何一条）或内容相同（和本机的文本类收藏、和文件里前面的片段）的跳过，其余加进来，都是收藏；
  关键字和本机收藏撞了，导入的那条去掉关键字，撞了的关键字（带前缀）在摘要里列出来（最多列 10 个）。
  文件里自己重名的关键字照原样（同本机规则：匹配时取最新的一条）。
- 听写历史、专注历史：按 id / 起止时间去重后合并，按时间排序，照各自的上限截断（听写 = 设置里的条数上限，
  专注 = 400 天）。听写合并后超过上限、最旧的被截掉时，摘要多一句「听写历史最多留 N 条，只留最新的；可以在 设置 → 语音听写 里调高。」
- 提醒项：同 id 的跳过，新的加进来，从现在开始计时；设置键只在本机还是出厂值（没设过，或设的就是出厂值）时才用导入的值
  （不改用户已经改过的设置），类型不对、超出范围、不认识的值跳过，和本机一样的不写。
- 文件格式不对 / 版本更高：提示看不懂（「它不是 Baobox 导出的备份」/「它是更新版本的 Baobox 导出的，请先升级」），什么都不改。
  文件本身打不开（没权限等）提示系统给的原因。能读的文件里，某一节缺了或类型不对当它是空的，坏条目逐条跳过。
- 确认弹窗开着时专注的计时器照走（可能刚好记下一轮），所以点「合并」后按当时的样子重算一遍再写回，同一拍里做完。

## 4. 代码

| 文件 | 职责 |
|---|---|
| `mac/Sources/Settings/DataExport/BaoboxBackup.swift` | 文件格式、编解码（容错）、导出取哪些、导入合并规则（`BackupMerge.plan`）。纯函数，不碰界面、不碰单例 |
| `mac/Sources/Settings/DataExport/PersonalDataTransfer.swift` | 保存 / 打开面板、摘要弹窗；从各模块取数据、写回各模块（主线程），编码、解码、读写文件在后台 |
| `mac/Sources/Settings/GeneralSettingsView.swift` | 「数据」分组 |
| `ClipboardStore.importSnippets` / `DictationHistoryStore.replace(with:)` / `DictationHistoryCodec.importing` / `FocusHealthController.importItems` / `importHistory` | 各模块的写回入口 |

写回各模块的存储都走各自原来的落盘路径，写失败按 #101 报（`StorageWriteFailure`；听写历史原来是 `try?`，这次一并改成上报）。

探针（编进真实文件跑）覆盖：导出 → 编码 → 解码与导出的一致、导入到空 Mac 后再导出内容一致、重复导入不产生重复条目、
片段关键字冲突、内容 / id 重复跳过、敏感条目与图片背景不导出、设置键只改出厂值的、听写上限截断、
版本更高 / 格式不对 / 不是 JSON 的文件被拒、坏条目逐条跳过。

## 5. 不做

- 不做定时自动备份、不做云同步。
- 不做「整个文件夹打包」（见 §1）。

## 6. 和设计稿不一样的地方

- 片段多带了 `id` 和 `type`（text / link）：去重要用 id（「id 相同的跳过」），链接类收藏导回来还是链接。
- 摘要里每一类都写「新几条」，提醒项、专注记录也写（设计稿的例子只给了片段和听写）；另加了专注设置会改几项、听写上限截断的说明。
- 设置键的「出厂值」按「没设过，或设的就是出厂值」算；背景图片路径不导出（换了电脑路径不在）。
- 导出 / 导入的结果显示在按钮下面那行小字里，出错用弹窗。
