# 本地模型（部署、启动、给功能用）设计

> issue #86 的延伸。2026-11-09 用户在 Ollama 里测试 `deepseek-r1:14b`（约 9 GB，Mac 是 16 GB 内存）时整机卡死，
> 提出把本地模型单独放一块：检测内存、建议装哪个、有下载和启动按钮、可以开机自启、用下拉框选模型。
> 用户定：放进「AI」页（最上面一块），只提供 Qwen3 系列。之后又改了两次：
> - 「AI」页改成三栏（功能 / 本机模型 / 云端模型），本地模型是第二栏（docs/ai-service/DESIGN.md §6.1）；
> - 模型清单扩到常见的十几个，加「自定义（粘贴 Hugging Face 链接）」（用户选 A）。

## 1. 需求

- 「AI」页最上面一块「本地模型」：
  - **这台 Mac**：芯片、总内存、现在可用的内存、磁盘剩余。
  - **推荐说明「怎么选」**（2026-11-09 用户要求）：按这台 Mac 的内存生成，每个用途推荐一个模型并写明为什么。
    翻译 → Hy-MT2（翻译专用、快且准，「自动」的离线后备）；字幕实时纠错 → Qwen3-1.7B（最快，大模型跟不上语速）；
    纪要、周报、润色 → 跑得动的最大的 Qwen3（写得好，会后整理不怕慢；内存太小就还是 1.7B）；不建议 → 「内存不够」的那些（橙色）；
    想要效果更好 → 云端模型（不占内存，但要 Key、付费、内容会发出去）。
  - **安装模型**：下拉框选模型，每项标「推荐 / 可以用 / 内存不够」；选中后显示文件大小、运行时大约占多少内存、适合做什么；「下载」按钮（下载中显示进度、暂停、取消）。
  - **已安装**：每个模型一行，显示状态（未运行 / 启动中 / 运行中 · 占用 X GB），「启动 / 停止」，「开机自启」开关，「删除」。
- **六个模型统一管理**（2026-11-09 用户要求：「可以列出来、写个推荐，但还是统一管理比较好」）：Hy-MT2-1.8B、Qwen3-1.7B 不再是「内置」特例，
  它们本来也是按需下载的。同样在安装下拉框里，装了才出现在列表里，同样能启动、停止、开机自启、删除；只是两类功能默认用它们。
- 所有本地模型都在各功能下拉框的「本机」一组里，没下载的标「未下载」（同云端模型的「未配置」），不用再添加服务商。
- 启动前查一次可用内存，不够就先确认，别再一下把内存占满。
- Ollama（作为服务商）也加保护：显示模型大小，太大时测试前先确认；本机服务的报错不再写「云端」；第一次加载慢，测试等久一点。

- Qwen3 用官方仓库（Hugging Face → ModelScope 两个地址）；Gemma 3 用 `ggml-org`，其余用 `bartowski` 的量化（只有 Hugging Face）。
  大小和 SHA-256 都是 2026-11-09 从 Hugging Face API 取的。
- **推理模型**（DeepSeek-R1 蒸馏）思考很长：上下文开到 8192（内存多估 0.5 GB），输出上限多给 3072；清理后还以 `<think>` 开头
  （想到一半就到上限、没有答案）当失败，退回这一类的默认模型，不把思考过程当结果。
- **推荐只在 Qwen3 里挑**（提示词按它调过、中英文都好）；其它家的模型照样按内存分「可以用 / 内存不够」。
- **自定义**：粘贴 Hugging Face 上 GGUF 文件的链接（`/resolve/` 或 `/blob/` 都行）→ 用 Hugging Face API 列出所在目录，取这个文件的
  大小和 LFS SHA-256 → 记进 `localmodel.custom`（JSON）→ 开始下载（同样做内存、磁盘检查和双重校验）。文件名前面加上 id，
  免得两个仓库里同名的文件互相覆盖；删掉时连记录一起删。效果和速度不保证，界面上写明。

- 文件都来自 Qwen 官方的 GGUF 仓库，按顺序试 Hugging Face → ModelScope。大小和 SHA-256 写死在代码里（2026-11-09 从 Hugging Face API 取的），
  下载完双重校验，同内置模型。
- **运行约占内存** = 文件大小 + 1 GB（4096 上下文的 KV 缓存加计算缓冲，偏保守）。
- 用 Baobox 自带的 llama-server 跑（同内置模型），每个模型一个 `OfflineTranslator` 实例：下载、断点续传、进程、空闲退出都沿用。
  模型文件放在 `~/Library/Application Support/Baobox/Translation/models/`，和内置模型同一个目录。

## 3. 推荐规则

按总内存 T 算（运行约占内存记为 M，都按字节算；16 GB 的 Mac 是 17.18e9 字节）：

| 条件 | 标签 |
|---|---|
| M ≤ 0.45 T 中最大的那个 | **推荐** |
| M ≤ 0.45 T 的其它 | 可以用 |
| 0.45 T < M ≤ 0.55 T | 占内存较多 |
| M > 0.55 T | **内存不够**（会卡顿，不建议） |

16 GB：8B（6.1e9 字节，36%）推荐，14B（10.1e9，59%）内存不够，和这次卡死的实际情况一致。8 GB：4B（42%）推荐。
24 / 32 GB：14B 推荐，30B-A3B 内存不够；48 GB 起 30B-A3B 推荐。最初定的 0.5 / 0.62 按 GB 估算，换成字节后 14B 在 16 GB 上只算「占内存较多」，所以收紧。
选了「内存不够」的模型，点下载时先确认一次。

## 4. 启动、停止、常驻

- **启动**：先查可用内存（`host_statistics64`：free + inactive + purgeable + speculative 页）。不够 M 就弹确认：
  「现在可用内存约 X GB，启动 <模型>（约 Y GB）可能让电脑变慢，确定启动吗？」。确认后拉起推理进程并**常驻**，直到点停止或退出 Baobox。
- **停止**：结束推理进程，同时解除手动启动的常驻。之后哪个功能再用到它，会按需重新拉起（同内置模型：用到时加载，空闲 10 分钟退出）。
- **开机自启**（`localmodel.<id>.autostart`）：Baobox 启动时把这些模型拉起来并常驻。打开开关时如果没在运行，就立刻启动；关掉开关只解除常驻，不立刻停。
  Baobox 自己的「登录时启动」在「通用」页，开关下面给一句提示。
- **状态**：未运行 / 启动中 / 运行中 · 占用 X GB。占用读推理进程的实际内存（`proc_pid_rusage` 的 phys_footprint），每 3 秒刷新一次，只在「AI」页开着时刷新。

## 5. 给功能用

- 新增选择 `localmodel:<id>`（`AIEngineChoice.localModel`）和路由 `AIRoute.localModel(id)`。这一类功能的**默认本地模型**
  （翻译 = Hy-MT2，通用 = Qwen3-1.7B，`LocalModels.defaultEntry`）存成 `.local`，`AIFeatureSettings` 读的时候也把
  `localmodel:<默认的 id>` 归一成 `.local` —— 同一个模型只有一种写法，老设置（`local` / `offline`）不用迁移。
- 下拉框：翻译类功能是「自动 / 系统翻译」，然后一组「本机」列出全部六个；通用类功能的「本机」一组列出五个 Qwen3（翻译专用的 Hy-MT2 不能做通用生成）。
  没下载的标「未下载」，选了它下面写「还没下载，到「AI」页最上面下载」；运行时没下载就用这一类的默认模型（同以前）。
- 字幕条状态行统一写「本机：<模型名>」，默认的离线翻译也一样（以前写「离线模型」）。
- 通用生成直接调这个模型；翻译用和云端一样的提示词（`AIPrompts.translation`），加 `/no_think` 关掉思考。
- 出错（进程起不来、超时等）就退回内置的本地模型，标 `usedFallback`，同云端。
- 常驻：字幕翻译、纠错、纪要、周报、听写期间，对**实际要用的那个**本地模型 `beginKeepAlive`（内置或可选的都一样），云端则不加载。
- 字幕的草稿降频同云端：大模型每句要几百毫秒到几秒，草稿每 2 秒最多一次。
- 字幕条状态行写「本机：Qwen3-8B」。
- 选的模型被删除了：按默认处理（同云端模型被删）。

## 6. Ollama 保护

- 拉 Ollama 的模型列表时，顺带用它的原生接口 `GET {根地址}/api/tags` 读每个模型的大小（`/v1` 去掉就是根地址）。
- 模型行显示「约 9.0 GB」。运行约占内存（文件 + 1 GB）超过 0.55 T 时标橙色：「这个模型约 9 GB，本机 16 GB 内存，加载时可能整机卡顿」。
- 「测试」前如果模型太大，先确认；本机服务测试超时放宽到 120 秒（第一次加载要把整个模型读进内存）。
- 报错措辞：地址指向本机时，超时写「本机服务响应超时（大模型第一次加载要一会儿）」，连不上写「连不上本机服务（Ollama 启动了吗？）」。

## 7. 「AI」页布局（对齐整理）

用户反馈服务商展开后很乱：说明文字有的居中、有的靠左，名字输入框没有边框还被截断，各行缩进不一致。改成：

- 服务商展开后的内容放进**一个**表格（`Grid`）里：左列是固定宽度的标签（名字 / 地址 / API Key / 模型），右列是控件；说明文字都放在右列、左对齐；
  输入框都有边框。模型列表在「模型」一行的右列：显示名称 | 模型名（组合框）| 测试 | 删除，下面一行小字（测试结果、用在哪些功能）左对齐。
- 「刷新列表」「添加模型」放在模型列表下面一行；「删除这个服务商…」在最下面，靠右。
- 本地模型那一块也用同样的表格对齐。
