# 文本片段（Snippets）

对应 issue：[#15](https://github.com/qiaob/baobox_mac/issues/15)

## 核心判断：片段 = 手工创建的收藏条目

不新立模块，也**不新开数据源**。收藏这条线已经把片段需要的生命周期全实现了 ——
`ClipboardStore` 里 `isPinned` 的条目：

- `clearAll()` 只删 `!isPinned`；
- `pruneExpired()` 只删 `!isPinned && createdAt < cutoff`；
- `enforceLimit()` 淘汰时只挑 `!isPinned`；
- `sortItems()` 里收藏永远置顶。

「手工维护、长期存在、绝不被淘汰」已经是现成的。片段要的就是这个，于是：

```
片段 = isPinned == true 的条目 + title/keyword 两个可选字段
```

落盘加密（`ClipboardCrypto`）、面板搜索、↑↓ 选择、⏎ 经 `PasteService` 回填粘贴、
按 App 忽略名单——全部直接继承，**检索路径零改动**：⌘⇧V → 收藏 → 搜索 → ⏎。

## 数据模型

`ClipboardItem` 加两个可选字段：

| 字段 | 用途 |
|---|---|
| `title: String?` | 片段展示名，缺省时界面回落到内容首行 |
| `keyword: String?` | 关键字触发词（不含前缀），有值即参与展开 |

`isSnippet` = `isPinned && (title != nil || keyword != nil)`——用来把「专门写的片段」
与「顺手复制后收藏的东西」在管理界面里分开，两者仍住在同一个数组里。

**向后兼容**：该结构体本来就手写了 `CodingKeys` + `init(from:)`，新字段一律
`decodeIfPresent`。老的 `clipboard.dat` 里没有这两个键，合成的 `Decodable` 遇到缺键会
**整份解码失败、用户历史一次性清空**——这正是当年加 `isConcealed` 时踩过的坑，文件里
的注释还留着。

新建片段走 `addSnippet` 而不是 `add(_:)`：后者带「与最近一条内容相同就合并」的去重逻辑，
对手工创建的片段是错的（用户完全可能就是要存一条和刚复制的东西一样的片段）。

关键字重名**不做写入侧去重**：设置页是边打字边保存的，中间态（`m` → `ma` → `mail`）
会顺手把别人的关键字抹掉，用户根本不知道发生了什么。重名交给匹配侧——
`snippet(forKeyword:)` 取列表第一条，收藏本来就置顶且顺序稳定，结果对用户是可预期的。

## 关键字展开

`SnippetExpander`，CGEventTap 监听 keyDown，与 `HotkeyCenter` 的菜单跟踪 tap 同一套写法
（类**不**标 `@MainActor`，因为 C 回调不能捕获隔离上下文；tap source 挂主 run loop，
内部用 `MainActor.assumeIsolated` 过渡）。

### 隐私边界（这一节是设计的第一章，不是最后一章）

- **默认关**，用户必须在设置里显式打开；
- 内存里只维护 **≤32 字符**的滚动缓冲，**绝不落盘、绝不进剪贴板历史、不做任何统计**；
- ⏎ / ⇥ / 空格 / esc / 方向键 / 任何带 ⌘⌃⌥ 的组合键**立刻清空缓冲**；
- 前台 App 在剪贴板忽略名单里就不展开（终端、密码管理器由用户自己列）；
- 密码框等开启 secure input 的场景，系统根本不会把按键投递给 event tap ——
  这是系统给的保护，不靠我们自觉；
- 没有辅助功能权限时静默不启用（设置页给一行橙色提示，不弹窗打扰）。

### 展开的事件时序

命中后**吞掉触发词的最后一个字符**（tap 返回 nil），所以只需要退 `n-1` 次格：

```
吞掉最后一击 → [下一拍] 退格 ×(len-1) → [+40ms] 写剪贴板 + 合成 ⌘V → [+350ms] 还原剪贴板
```

**退格必须推到下一个 runloop tick 再发**：命中时还在 tap 回调栈里，回调尚未返回、
当前这一击也还没被丢弃，在那里同步 post 事件等于往自己正在处理的队列里插队，顺序不可控。

三个延迟都是必要的：

- 退格与粘贴挨太近，部分 App 会把两者顺序颠倒；
- 剪贴板还原太早，目标 App 还没读完就被改回去，粘出来的是旧内容；
- 写剪贴板前后都要置 `monitor.ignoreNextChange = true`，否则片段内容和被还原的旧内容
  会各自进一次历史。

`isExpanding` 标志挡住递归：自己合成的退格与 ⌘V 会再次流经本 tap。

## 管理界面

放在**剪贴板设置页**新增的「文本片段」一节：列表（名称 + 关键字就地编辑）、新建、
展开内容编辑（`TextEditor`）、删除，以及展开功能的三个开关。

列表列的是**所有文本类收藏**，不是只列「带标题或关键字的」——否则「给已有收藏补一个
关键字」就永远没有入口，而那正是最自然的录入路径（顺手复制 → 收藏 → 想起来给它设个触发词）。
专门写的片段排在前面，没起名字的条目补一行内容预览，否则光看空输入框认不出是哪条。

面板侧本次**不改**：片段本来就是收藏，⌘⇧V → 收藏分区已经能搜到、能 ⏎ 粘贴。
行内的关键字角标属于锦上添花，等这个功能真用起来了再说。
