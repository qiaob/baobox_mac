# 局域网传输 —— 需求

对应 issue #23。

## 一句话

Mac 上开一个临时的局域网 HTTP 接收服务，手机扫菜单里的二维码打开网页，选文件上传到 Mac，
传输中与完成后 Mac 端出通知；服务能在合适的时机自动或手动关闭。

## 场景

手机上拍的照片、微信里存的文件、iPad 上导出的 PDF，要弄到 Mac 上。
现有办法都别扭：AirDrop 时灵时不灵且只在 Apple 设备之间、微信文件传输助手糊图、
U 盘要转接头、网盘要等同步。局域网直传是最快的一条路，缺的只是一个「随开随用」的入口。

**方向明确：只做「手机 → Mac」的接收。** 反向（Mac → 手机）不在本期范围内，
理由见「非目标」。

## 功能需求

### F1 开关与入口

- 菜单栏二级菜单里一个开关：**开始接收 / 停止接收**。默认关闭。
- 开启后菜单里显示：本机地址 `http://<局域网IP>:<端口>`（点击复制）、**内嵌二维码**、
  剩余自动关闭时间、当前传输进度。
- 快捷键：出厂不绑定（`defaultCombo: nil`），可在快捷键页自设「开始/停止接收」。

### F2 手机端网页

- 扫码打开的页面必须**零外部依赖**（不加载任何 CDN 资源）——手机可能没有外网。
- 页面能力：
  - 选择文件（多选）、拍照直传（`capture` 属性）、**把文件拖进页面**（桌面浏览器）
  - 逐个显示上传进度条、成功 / 失败状态
  - 显示保存到 Mac 的哪个目录（只读文本，不暴露完整路径以外的信息）
- 中英文两版文案，按手机的 `Accept-Language` 选。
- 断线、被拒、服务已关闭要有明确提示，不能卡在转圈。

### F3 保存

- 默认保存到 `~/Downloads/Baobox`，设置页可改（目录选择器）。
- 目录不存在自动创建；不可写时**报错并提示**，不静默失败。
- 重名不覆盖：追加 `-2`、`-3` 序号。
- 文件名消毒：去掉路径分隔符与 `..`，防目录穿越。

### F4 通知

- **开始接收**：收到第一个文件的第一个字节时发一条通知（可关）。
- **接收完成**：每个文件落盘后发一条，含文件名与大小；点击通知在访达中显示（可关）。
- 传输进行中，菜单里能看到实时进度（打开菜单时刷新，不常驻轮询）。

### F5 安全与自动关闭（issue 的重点）

| 措施 | 说明 |
|---|---|
| 默认关闭 | 不开机自启，不后台常驻。关闭态零监听、零线程 |
| 一次性访问码 | 每次开启生成新的随机 token，二维码里带；**请求不带正确 token 一律 404** |
| 只收不发 | 服务端没有任何「读本机文件」的路由。手机端只能上传，无法浏览或下载 Mac 上的东西 |
| 空闲自动关闭 | 默认 10 分钟无活动自动停（可设 5 / 10 / 30 分钟 / 不自动关） |
| 完成后关闭 | 可选：所有传输完成后立即停（默认关） |
| 睡眠 / 锁屏关闭 | Mac 睡眠或屏幕休眠时自动停 |
| 退出关闭 | App 退出必停（`willTerminate`） |
| 单文件上限 | 默认 4 GB，可设。超限直接拒绝，不占磁盘 |
| 仅局域网 | 只绑局域网端口，不做端口映射 / 内网穿透。菜单里明示「仅同一 Wi-Fi 可见」 |

## 非目标

- **Mac → 手机的下发**：那需要在服务端开放本机文件读取路由，与 F5「只收不发」直接冲突，
  安全模型完全不同。要做得单独设计（例如仅暴露用户显式选中的单个文件、单次有效链接）。
- **HTTPS**：局域网内自签证书会让手机浏览器弹警告，体验反而更差；
  且传输内容只在同一 Wi-Fi 内、有 token 保护、服务短时开启。本期用明文 HTTP。
- **断点续传 / 秒传 / 文件夹上传**：一次性传输场景用不上，徒增复杂度。
- **设备配对记忆 / 历史设备列表**：与「一次性 token」的安全模型冲突。

## 验收

1. 手机与 Mac 同一 Wi-Fi，扫码即开页面，选 3 张照片能全部传到 `~/Downloads/Baobox`。
2. 传输中拔掉手机 Wi-Fi，Mac 端该文件标记失败，**不留下半截文件**。
3. 关掉服务后再刷新手机页面，提示「服务已关闭」而不是无限转圈。
4. 改掉二维码 URL 里的 token 去访问，得到 404。
5. 开启后不操作，10 分钟后自动关闭，菜单开关回到关位。
6. 传 1 GB 大文件，Mac 内存占用不随文件大小上升。
