# 手机互传 —— 需求

## 1. 目标

Mac 和手机之间互传文件和文字。手机**不装 App**：用相机扫 Mac 上的二维码，在浏览器里打开网页就能用。

两种模式：

| | 局域网模式（默认） | 公网模式 |
|---|---|---|
| 适用 | 手机和 Mac 在同一个 Wi-Fi | 不在同一个网络（手机走流量、在别处） |
| 手机网页从哪来 | Mac 自己开的 HTTP 服务 | GitHub Pages（本仓库的静态页） |
| 传输 | 纯 HTTP（上传 / 下载） | WebRTC DataChannel（P2P，UDP 打洞） |
| 外部依赖 | 无，断网也能用 | 公共信令（ntfy.sh、EMQX / HiveMQ 公共 MQTT）+ 公共 STUN |
| 中继 | — | **不做**。两边 NAT 都打不通时明确提示原因和替代办法 |

## 2. 用户故事

1. 菜单栏 → 手机互传 → 打开窗口，默认显示局域网二维码。
2. 手机扫码打开网页，Mac 窗口里出现「某某设备请求连接 [拒绝] [允许]」，点允许后连上。
3. 手机选文件发给 Mac：存进接收文件夹（默认 `~/Downloads/Baobox`），窗口里显示进度，传完可「在 Finder 中显示」。
4. Mac 拖文件进窗口（或点「选择文件…」）：手机网页上出现这个文件，点一下下载。
5. 手机发一段文字：Mac 窗口里显示，可一键复制（设置里可选自动复制到剪贴板）。Mac 也可以发文字给手机。
6. 不在同一网络：切到「公网」，扫新的二维码，流程同上。连接成功后显示连接方式（局域网直连 / 公网直连）。
7. 公网连不上：约 20 秒内给出失败原因（例如「手机网络是对称型 NAT」「UDP 被拦截」）和办法：连同一个 Wi-Fi、电脑连手机热点、换网络。

## 3. 功能要求

### 3.1 会话

- 二维码只对当前窗口有效：关窗即结束会话（局域网停掉 HTTP 服务，公网断开 P2P），下次打开换新的令牌 / 密钥。
- 每个新设备都要在 Mac 上点「允许」；拒绝后该设备在本次会话内不能再请求。
- 局域网模式可以同时连多部手机；公网模式一次连一部（再连要点「新会话」重新生成二维码）。

### 3.2 安全

- 局域网：URL 里带 128 位随机令牌，没有令牌的 API 请求一律 403；还要 Mac 端点允许。局域网内是明文 HTTP，界面上标注「同一 Wi-Fi 下的其他人理论上可以窃听，在公共 Wi-Fi 上建议用公网模式」。
- 公网：二维码 `#` 后面带会话 ID 和 256 位密钥（`#` 后的内容浏览器不发给任何服务器）。信令消息用 AES-GCM 加密并认证，公共信令服务看不到内容，也伪造不了 SDP；文件走 WebRTC 的 DTLS 端到端加密，不经过任何服务器。
- 二维码 10 分钟没人扫就过期，点「刷新」重新生成。

### 3.3 不做

- 中继（TURN）、断点续传、文件夹整体传输（可以多选文件）、传输历史持久化、手机原生 App。

## 4. 设置

| 项 | 默认 |
|---|---|
| 接收文件夹 | `~/Downloads/Baobox` |
| 收到文字自动复制到剪贴板 | 关 |
| 公网模式的手机页面地址（高级，fork 仓库自己部署 Pages 时改） | `https://qiaob.github.io/baobox_mac/transfer/` |

快捷键「打开手机互传」，出厂不绑定。
