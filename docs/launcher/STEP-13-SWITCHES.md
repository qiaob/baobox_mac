# 第 13 步 · 设置里列出全部功能，每一项都能关

> 2026-11-25 设计。分支 `feat/launcher-feature-switches`，worktree `~/cmb/worktrees/baobox-launcher-pr13`，基于第 10 步（`feat/launcher-more-actions`）。
> 工作规则见同目录 `WORKFLOW.md`。完成后本文的内容并入 `REQUIREMENTS.md` / `TECH_DESIGN.md` §11，本文件可删。

## 背景

用户（2026-11-25）：「在快速入口的设置中，加一些设置项，是否开启某些功能，比如生成二维码，比如搜索文件等等，全部列出来。」

快速入口现在能做的事已经有四十来样，全都默认出现。用户要的是：设置页把它们**全部列出来**，每一项一个开关，不想要的关掉。这一页同时也是功能清单 —— 新用户看一遍就知道快速入口能做什么（设置页即说明书）。

现在的设置页只有快捷键和两行开关（呼出时带上选中的文字 / 刚复制的内容）。

## 设计

### 1. 一项功能 = 一个 id，关掉的记在一个集合里

- 设置键 `launcher.disabledFeatures`：字符串数组，存**被关掉的** id。不在里面的都是开着的 —— 以后新加的功能默认开，不用迁移。
- 第 9 步的两个键 `launcher.context.selection` / `launcher.context.clipboard` 并进来（id 见下表），旧键删掉。第 9 步还没装到用户机器上，不用迁移。`TECH_DESIGN.md` §11 里计划过的 `sources.<来源 id>` 也由它取代，表格跟着改。
- 纯逻辑放 `Modules/Launcher/Logic/LauncherFeatures.swift`（只 import Foundation，有单元测试）：
  - `LauncherFeatureID` 的拼法（见第 2 节）；
  - `LauncherFeatureSet`：给一个被关掉的集合，回答 `isEnabled(id)`；
  - 设置页的分组与排序规则（给一批声明，产出分好组、排好序的行）。
- 读设置：每次呼出（`show()`）读一次，存成内存里的 `LauncherFeatureSet`，到收起为止不变。打字路径只查这个集合。设置页里拨开关直接写 `UserDefaults`，下次呼出生效。

### 2. 有哪些项（设置页就照这个分组和次序列）

id 的拼法：框架自己的功能用固定 id；来源用 `source/<来源 id>`；模块声明的动作用 `action/<命令 id>`（文字、图片、文件动作都是 `LauncherCommand`，id 现成）。

**搜索**（输入文字时在哪些地方找）

| id | 名字 | 说明（行下的小字，一句） |
|---|---|---|
| `source/apps` | App | |
| `source/commands` | Baobox 的命令 | 截图、防休眠、开始专注… |
| `source/<来源 id>` | 各模块的来源：剪贴板历史、文本片段… | 名字用 `launcherSourceName` |
| `source/files` | 文件 | 按文件名找 |
| `source/path` | 路径 | 输入或贴进一个路径时，打开它、列出文件夹里的内容 |

**直接给结果**（输入符合某种样子时，第一行直接给出）

| id | 名字 | 说明 |
|---|---|---|
| `instant/calculator` | 计算 | `12*(3+4)`、`5 km to mi`、`0xff`（实现时改：计算引擎没有汇率，`100 usd to cny` 算不出来） |
| `instant/textFormat` | 识别文本格式 | JSON、JWT、时间戳、Base64… |
| `instant/url` | 网址 → 打开 | |
| `instant/email` | 邮箱 → 写邮件 | |
| `instant/color` | 颜色值 → 预览和换算 | |
| `instant/wordCount` | 一大段文字 → 字数 | （实现时补：代码里有、表里漏了） |
| `instant/reminder` | 带时间的句子 → 提醒 | 「20 分钟后提醒我取快递」 |

（url / email / color 现在是不是各自一行、有没有哪一样其实没做，以代码为准：没有的不列，回报里说明。）
实现时核对：url（含有歧义网址在兜底组第一条的「打开」）、email、color（三行）都各有一个开关；都在。

**文字的去处**（放进一段文字后的建议）

- 框架自己的：`suggest/webSearch` 上网搜、`suggest/fileName` 搜文件名、`suggest/runInTerminal` 在终端里运行。
- 各模块声明的文字动作，每条一行，id `action/<命令 id>`：翻译、学习、解释、总结、润色、朗读（划词助手），存为片段、钉成贴卡、生成二维码（剪贴板），发到手机（手机互传），交给 Claude Code，交给 Codex，入会并开始会议记录（会议）。
- 名字 = 命令的标题；行右侧的小字 = 所属工具名。
- 次序：按默认档位（`suggestion.priority`），同档按声明顺序 —— 和面板里默认的次序一致。

**图片的去处**（放进一张图片后的建议）

- 框架自己的（实现时补）：`image/recognition` 识别图里的文字和二维码 —— 挂着图片时最前面的识别结果几行（「正在识别…」、二维码、识别出的文字）。关掉只是不出这几行，取字照样在后台跑（「<命令名>图里的文字」要用）。
- 各模块声明的图片动作，`action/<命令 id>`：取字、钉在屏幕上、预览、保存成文件（截图），把图片发到手机（手机互传）。
- 「翻译图里的文字」这类由文字动作派生的行不单列：关掉「翻译」它也跟着没有。在这一组的页脚写一句说明。

**文件和文件夹的去处**（路径行后面的动作）

- 框架自己的：`path/openInTerminal` 在终端里打开、`path/copyPath` 复制路径。
- 各模块声明的文件动作，`action/<命令 id>`：发到手机。

**刚呼出、还没打字时**

| id | 名字 | 说明 |
|---|---|---|
| `context/selection` | 带上你选中的文字 | |
| `context/clipboard` | 带上你刚复制的内容 | 5 分钟内复制的 |
| `context/situational` | 按当前情况给建议 | 会议快开始、正在专注、正在录屏… |
| `context/frequent` | 最常用的 | |

情景建议不按模块拆开（哪些模块会给建议取决于当时的状态，列不全）；一个总开关。

### 3. 列表怎么来（框架不认识具体工具）

- 来源：`registry` 里各模块的 `launcherSources()`，用 `launcherSourceID` / `launcherSourceName`。
- 动作：各模块的 `launcherCommands()` 里的文字、图片、文件动作；所属工具名 = 声明它的模块的 `name`。
- 框架自己的功能：一张静态表（id、名字的本地化 key、说明的 key、图标、属于哪一组）。
- 设置页出现时收集一次（`onAppear`，主线程，只读内存 —— 和每次呼出时做的是同一件事）。没安装 Claude Code 时它不声明「交给 Claude Code」，这一行自然就没有。
- id 带动态内容的命令（`claudecode.waiting.<会话>`）不是文字 / 图片 / 文件动作，不会进这张表。
- 被关掉的 id 即使这次没人声明（工具暂时不可用），也**留在**设置里不清理 —— 不然工具回来后开关状态丢了。

### 4. 关掉之后的行为

关掉 = 这一项不在快速入口里出现。工具本身不受影响（划词助手照样能翻译，剪贴板面板照样能生成二维码）。页面最上面用一句话说清楚这一点。

- **来源**关掉：不收集它的条目；它的前缀也跟着失效（关掉文件后输入 `f readme` 按普通文字处理）。`suggest/fileName`（改写成 `f <文字>`）在文件来源关掉时也不出。
- **路径**关掉：贴进一个路径按普通文字处理（仍有文字的建议）；路径行后面的动作自然没有。
- **直接给结果**的关掉：不出那一行，输入仍按普通文字给建议。关掉提醒后，输入「提醒」也不再列出待响的提醒 —— 但已经设好的提醒照常响（提醒中心不受开关影响；界面上不用为这一点加文字）。
- **动作**关掉：文字、图片、文件三处都不出；由它派生的「<命令名>图里的文字」也不出。
- **情景**的四项：各自不出。`context/selection` 关掉时**不读选区**（不做那次 AX 调用），不只是不显示。
- 使用记录不动：关掉再打开，原来的排序还在。
- **全关也不能卡住**：非空输入在所有建议都被关掉时，出一行不可选的小字「建议都关掉了，可以在设置里打开」（现有的「没有结果」那个位置）。空输入什么都没有时照旧显示那行提示文字。
- 二次确认、焦点、选中规则都不动。过滤发生在**收集**那一步（每次呼出一次）和建议计划里（纯内存），不在视图里。

### 5. 设置页的样子

沿用现在的 `Form` + `.formStyle(.grouped)`：

1. 现有的第一节不动（一句话说明、快捷键、冲突提示）。
2. 一句话：「下面是快速入口能做的全部事情。关掉的只是不在这里出现，工具本身不受影响。」
3. 六个小节，标题就是第 2 节的六个组名，**全部展开**（用户要的是全部列出来，不折叠）。
4. 每行：图标（命令或来源自己的 SF Symbol）+ 名字 +（有的话）右侧次要色小字写所属工具名 + 开关。有说明的在名字下面一行小字。一行只说一件事，不加别的按钮。
5. 每个小节标题右边一个小的文字按钮「全部打开」/「全部关闭」（这一节里有关着的就显示「全部打开」，否则显示「全部关闭」）。
6. 原来那两行开关（选中的文字、刚复制的）搬进最后一节，不再单独成节。
7. 页面比较长：确认设置窗口这一页能滚动；渲染图里看整页。

所有文案走 `L()` / `Text()`，en + zh-Hans。命令的标题、来源名、工具名是现成的本地化字符串，不新造。

### 6. 不做

每个来源的前缀自定义、搜索引擎列表的编辑、文件搜索范围的设置、别名、清除使用记录、⌘Space 引导（都是完整设置页的内容，另一步）；情景建议按模块拆开；改各模块自己的设置页。

## 实现记录（2026-11-25，和上文不一致或上文没写到的）

- 第 2 节的表：补了 `instant/wordCount`、`image/recognition`；计算的例子换成 `5 km to mi`。
- 来源关掉（第 4 节「不收集它的条目」）：模块来源的条目**照样取**（只读内存），但不交给引擎、前缀不生效、不建搜索键。原因：「刚复制的」从剪贴板来源的最新一条取，文件搜索的「剪贴板里出现过的路径」也从它抽；不取的话关掉「剪贴板」就连带关掉了「带上你刚复制的内容」，两个开关不再独立。剪贴板路径仍归「文件」管。
- `c ` 前缀属于剪贴板来源：关掉剪贴板、开着片段时，`c ` 失效，片段只在不带前缀时出现。
- `source/files` 关着时还不调 `LauncherFileSources.panelShown`（不建已知文件 / 剪贴板路径的表、不重扫），启动后那次扫描也跳过。
- 「最常用的」（`context/frequent`）只管输入框为空的那种；只打了前缀（`c `）时列出的用过的行不受它管。
- 「建议全关」的条件：没打前缀、输入不少于 2 个字符、一行都没有、「文字的去处」一项都没开着（模块的文字动作过滤后为 0、上网搜关着、搜文件名出不来、在终端里运行关着）。还有开着、只是不适用的（只开着「学习」、输入是中文）照旧是「没有结果」。文件还在搜时先是「正在查找…」。
- 设置页：小节标题后面同一行一句小字说这一组管什么时候（就是第 2 节每组括号里那句；「刚呼出、还没打字时」不用）；「全部打开 / 全部关闭」用链接样式（灰字看不出能点）；来源的图标用所属工具的（`LauncherSearchable` 没有图标），右侧工具名和来源名一样时不写（「剪贴板」那一行）；「在终端里运行」在「文字的去处」里排第一（它总是兜底组第一条）。
- 设置页的开关在离屏渲染里是非活动窗口的灰色（开着的旋钮在右边）；真机的设置窗口是活动窗口，开着的是强调色。

## 验证后定的（2026-11-25，设计者）

1. **挂着图片、图片的去处全关**：图片动作过滤后为 0、`image/recognition` 关着、没有带 `imageTextPriority` 的文字动作开着 —— 这时一行都没有，和文字全关一样，消息那一行是「建议都关掉了，可以在设置里打开」（原来显示的是空输入的提示文字「找 App、命令…」，带筛选词时是「没有结果」）。判断是 `LauncherFeatureRules` 的图片版，单元测试覆盖。
   实现者补：挂着图片时消息行不再用空输入的提示文字 —— 没全关、只是这次一行都没有（识别开着但图里没认出东西、动作全关；或者打的筛选词一个都没对上）时是「没有结果」。
2. **设置页里的行名不带动态内容**：`LauncherCommand` 加可选的 `settingsTitle`（nil = 用 `title`），设置页的行优先用它。交给 Claude Code / 交给 Codex（标题带最近的项目名）、朗读（正在读时是「停止朗读」）填固定的名字：「交给 Claude Code」「交给 Codex」「朗读」。框架照样不认识具体工具，别的命令不用填。
3. **关掉「路径」后，以 `/`、`~` 开头的输入不出「搜文件名」**：改成 `f ~/…` 之后文件搜索不接以 `/`、`~` 开头的查询词（`LauncherFilePolicy.fragment`），点了只得到「没有结果」。这种输入的兜底建议里不放这一条。

不改的（记在这里）：

- 「全部打开 / 全部关闭」只改这一节此刻列出来的 id（这次没人声明的、关着的那一项不动）。
- 来源关掉后条目照样取（见上面「实现记录」）。
- 关掉「计算」后，算式按普通文字处理，够长时也会去搜文件（和任何普通文字一样）。
- 空输入的提示文字是固定的（「找 App、命令、剪贴板、文件…还能算 12*(3+4)」），不跟着开关变。
